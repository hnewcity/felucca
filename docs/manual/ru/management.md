# Интерфейс управления и централизованная конфигурация

`felucca-server` предоставляет управление устройствами, службами, частным доступом и конфигурацией. Обычные изменения синхронизируются без перезапуска, неизменённые службы продолжают работу. Изменение инфраструктуры, например глобальных слушателей, перезапускает пересылку; API управления остаётся доступным.

## Подключение без редактирования конфигурации

1. В разделе **Устройства → Подключить устройство** задайте имя, подтвердите сервер и выберите систему и процессор. Распакуйте клиент и откройте `Connect.command` (macOS) или `Connect.cmd` (Windows). В Linux выполните `sh connect.sh` в распакованной папке. Программа и параметры уже включены, редактировать файлы не нужно.
2. В разделе **Службы → Добавить службу** выберите устройство, тип и адрес приложения на нём. Публичный доступ использует порт или домен сервера; частный доступ предоставляется разрешённым устройствам. Идентификаторы и секреты создаются автоматически.
3. Каждое принимающее устройство также получает собственный пакет клиента и использует показанный локальный адрес. Для автозапуска после входа закройте окно подключения и запустите `Install.command`, `Install.cmd` или `sh install.sh`. Клиент сохраняется в личной папке.

Основная навигация: обзор, устройства, службы, частный доступ, мониторинг и настройки. Учётные записи, квоты, диагностика, порты сервера и интеграции находятся в настройках. Для обычных и дополнительных операций используются элементы формы, без редактора JSON.

В настройках можно включить прямые соединения с переходом на ретрансляцию через сервер при неудаче. Если они отключены, используется ретрансляция. Это доступ к отдельным службам, а не общесистемная VPN. Для файлового доступа нужно разрешить существующую папку устройства. Файлы подключения содержат секреты: храните их безопасно. Сохраните исходный файл принимающего устройства или создайте новое частное подключение. Изменения устройств, служб и доступа не перезапускают всю пересылку. Изменённые или отключённые службы завершают свои соединения. Другие службы и переименование сохраняют соединения. Старый agent переподключает только затронутое устройство. Изменение слушателей bridge, HTTP и P2P по-прежнему перезапускает пересылку.

Предлагаются только сборки клиента, имеющиеся на сервере. Сборки macOS без нотариальной проверки Apple помечены и могут блокироваться после обычной загрузки. Запросите выпуск для распространения у администратора, не отключая защиту системы.

## Включение

```sh
target/release/felucca-server --hash-password      # read one password line from stdin; >=12 bytes
target/release/felucca-server --generate-token     # Bearer token and its stored hash
```

```toml
[admin]
bind = "127.0.0.1:8088"
state_path = "state/runtime-config.json"
profiling = true
# required for non-loopback binds: the origin the browser uses; use https://
# unless you accept plaintext management traffic (then http://host:port)
# origin = "https://admin.example.com"

[admin.account.root]
role = "admin"
password_hash = "pbkdf2-sha256$600000$..."
```

Файлы конфигурации могут быть в формате TOML или JSON. В примере используется адрес управления
`http://127.0.0.1:8088` и учётная запись `root`. Пароль из примера предназначен только для
локальной демонстрации; в реальных развёртываниях замените его собственным хешем.

## Учётные записи и роли

| `role` | Разрешения |
| --- | --- |
| `admin` | Управление всеми ресурсами и учётными записями; поле `user` не задаётся |
| `operator` | Управление узлами и централизованными туннелями назначенного `user` |
| `viewer` | Доступ только для чтения к ресурсам назначенного `user` |

Учётные записи операторов и наблюдателей должны ссылаться на существующего пользователя.
Локальные сервисы сервера могут обращаться к локальным каталогам, поэтому изменять их может только
администратор. Квоты пользователей, учётные записи администраторов и полная конфигурация также
доступны только администратору. Сохраняйте как минимум одну включённую учётную запись
администратора. Поле `disabled = true` отключает учётную запись.

Пароли используют PBKDF2-SHA256 со случайной солью и фиксированными 600000 итераций. Сеансы
хранятся в памяти. Cookie имеют признаки HttpOnly и SameSite=Strict, а при настройке HTTPS
дополнительно помечаются как Secure. Записи из браузера требуют одноисточного Origin и токена CSRF.
Смена пароля, отключение или удаление учётной записи аннулируют прежние сеансы, а перезапуск
процесса аннулирует и сеансы на основе Cookie.

Для автоматизации используйте Bearer-токен: скопируйте `token_hash`, выведенный командой
`--generate-token`, в поле `token_hash` учётной записи и передавайте сам токен с каждым запросом.
Запросы Bearer не требуют токена CSRF из Cookie, но проверки разрешений учётной записи применяются
так же. **Никогда не записывайте сам токен в конфигурацию сервера.**

## Транзакции записи

Каждая запись требует два заголовка:

```text
If-Match: "current configuration revision"
Idempotency-Key: unique identifier for this operation
```

- Устаревшая ревизия возвращает 409.
- Тот же идентификатор с тем же запросом возвращает прежний результат и **не** перезапускает
  плоскость данных заново; тот же идентификатор с другим запросом возвращает 400.
- Последние 256 успешных операций хранятся вместе с конфигурацией, поэтому повторы операций
  вроде DELETE распознаются и после перезапуска.
- Значение `durable = false` означает, что синхронизация каталога ещё не подтверждена.
- Изменения устройств, служб и доступа не перезапускают всю пересылку. Изменённые или отключённые службы завершают свои соединения. Другие службы и переименование сохраняют соединения. Старый agent переподключает только затронутое устройство. Изменение слушателей bridge, HTTP и P2P по-прежнему перезапускает пересылку.

Смена адреса привязки интерфейса управления, путей к файлам сертификатов, публичного источника или
пути состояния требует перезапуска процесса. Их нельзя изменить при работающем сервере.

## Страницы интерфейса

| Страница | Содержимое |
| --- | --- |
| Обзор | Состояние устройств, служб и соединений, доступных этой учётной записи. |
| Устройства | Выберите подключённый компьютер или сервер для управления сервисами. |
| Сервисы | Выберите устройство и приложение. Felucca подключит их к выбранному адресу. |
| Частный доступ | Выберите закрытый сервис и создайте файл для другого устройства. Публичный порт сервиса не нужен. |
| Мониторинг | Просмотр метрик хоста, числа соединений и накопленного трафика. |
| Настройки | Соединения сервера, права и интеграции. Повседневные действия доступны в основном меню. |

## API

API работает с JSON, принимает тела запросов размером до 2 MiB и отклоняет межсайтовые запросы из
браузера. Чтения обычно возвращают `{revision, config}`, а чтение конфигурации по умолчанию скрывает
секреты. При изменении существующий заполнитель `<redacted>` сохраняет текущее значение этого поля;
для учётных данных новых ресурсов этот заполнитель использовать нельзя.

| Путь | Метод и назначение |
| --- | --- |
| `/api/login` | POST `{account, password}`; Origin обязателен |
| `/api/session` | GET текущую идентичность и токен CSRF |
| `/api/logout` | POST для отзыва сеанса на основе Cookie |
| `/api/overview` | GET подключённые узлы, соединения, трафик и зарегистрированные туннели |
| `/api/users`, `/api/users/<id>` | GET списка или одной записи; PUT и DELETE для одной записи |
| `/api/clients`, `/api/clients/<id>` | GET списка или одной записи; PUT и DELETE для одной записи |
| `/api/managed/<client>` | GET, PUT всей централизованной конфигурации; DELETE восстанавливает локальную конфигурацию |
| `/api/managed/<client>/tunnels/<id>` | GET, PUT, DELETE одного туннеля |
| `/api/locals`, `/api/locals/<id>` | GET списка или одной записи; PUT и DELETE для одной записи |
| `/api/locals/<group>/tunnels/<id>` | PUT, DELETE туннеля локального сервиса сервера |
| `/api/shares`, `/api/shares/<name>` | GET, PUT, DELETE приватного общего доступа |
| `/api/accounts`, `/api/accounts/<id>` | GET списка; PUT и DELETE для одной записи |
| `/api/config` | GET полной конфигурации со скрытыми секретами; PUT для импорта полной конфигурации |
| `/api/config?secrets=1` | Доступный только администратору явный экспорт, включая учётные данные |
| `/api/validate` | POST для проверки полной конфигурации без запуска слушателей |
| `/api/batch` | POST атомарного пакета изменений, не более 128 операций |
| `/api/events` | GET SSE для изменений ревизии конфигурации, с пульсом раз в 10 секунд и повторной проверкой сеанса |
| `/metrics`, `/api/metrics` | GET метрик Prometheus, отфильтрованных по разрешениям учётной записи |
| `/api/profile` | POST для загрузки графика пламени процессора с ограниченным сроком действия |

Пакет использует одну ревизию и один идентификатор операции. Все операции проверяются до того, как
что-либо будет применено, и если хотя бы одна операция выходит за пределы полномочий или
конфигурация некорректна, ни одна из предыдущих операций не фиксируется:

```json
{
  "operations": [
    {
      "method": "PUT",
      "path": "/api/managed/office/tunnels/1",
      "value": {
        "id": 1,
        "enabled": false,
        "mode": "tcp",
        "port": 18080,
        "backend": [{"addr": "127.0.0.1:3000"}]
      }
    }
  ]
}
```

Когда вы отправляете `PUT` для учётной записи, можно передать поле `password`, и сервер сгенерирует
хеш. Если его не указать, сохраняется существующий `password_hash`.

## Централизованная конфигурация

Сервер хранит конфигурацию, в которой агенты должны работать, в секции `[managed.<client-id>]`:

```toml
[[managed.office.tunnel]]
id = 1
mode = "tcp"
port = 18080
bind = "127.0.0.1"
backend = [{ addr = "127.0.0.1:3000" }]
```

Агент должен явно включить `[remote] enabled = true`, а основное соединение должно использовать
аутентифицированные TLS/WSS/QUIC. Сервер также проверяет, что фактический мост зашифрован, поэтому
соединения открытого текста не могут запрашивать конфигурацию. Рассылка использует канонический JSON
с дайджестом, а учётные данные из конфигурации не попадают в отладочные журналы управляющих
сообщений.

Плоскость управления может изменять только содержимое туннелей. Она не может рассылать новые
личности агентов, прокси выхода или границы авторизации локальных сервисов сервера. Файловым
сервисам нужно заранее настроить их именованные возможности доступа к каталогам; см. [Файловые
сервисы и WebDAV](file-services.md).

Исключение: если агент задаёт `remote.console_scope = true`, поле `target_policy` в `[managed.<client-id>]` заменяет его диапазон назначений.

| Операция | Результат |
| --- | --- |
| `tunnel.enabled = false` | Сохраняет конфигурацию и стабильный идентификатор, но не регистрирует слушатель и не запускает проверку бэкенда |
| Сохранить пустую запись `managed` | Останавливает все централизованные туннели этого узла |
| Удалить всю запись `managed` | Восстанавливает локальную конфигурацию туннелей агента с момента запуска |

Страницы управления различают состояния «опубликовано», «ожидает применения узлом» и «отключено».

## Контрольный список проверки

1. Команда `felucca-server --config server.json --check` завершается успешно.
2. Откройте адрес управления в браузере, войдите и убедитесь, что ошибок JS нет.
3. Создайте TCP-туннель и убедитесь, что бэкенд действительно возвращает содержимое.
4. Запрос `GET /api/config` не показывает секреты в открытом виде.
5. После перезапуска сервера конфигурация и туннели остались на месте, а повтор с тем же
   `Idempotency-Key` не применяет изменение дважды.

Консоль предоставляет структурированные формы для весов и TLS бэкендов, проверок состояния, маршрутов HTTP, сервисных учётных записей, ACL и квот, файловых сервисов, групп локальных туннелей и диапазонов портов.  На странице учётных записей можно создавать, заменять и отзывать токены управления; новый токен скачивается после сохранения.

Проверка показывает настройки, требующие перезапуска. Экспорт содержит стартовые настройки, рабочий снимок с учётными данными и инструкции по замене при остановленном процессе. Сначала остановите процесс и сохраните копии файлов. Рабочий снимок имеет приоритет над стартовым файлом, включая путь из `--runtime-config`. Сохраните журналы трафика и платформы; не заменяйте снимок работающего процесса.

Диагностика показывает трафик туннелей, существующие результаты проверок бэкендов, активные сессии P2P и недавние события ретрансляции. Администраторы могут просматривать активные сертификаты, повторять неудачные запросы ACME, загружать сертификаты и ключи PEM в черновик и читать ограниченный конец журнала со скрытыми учётными данными. Старые агенты без дополнительного диагностического потока показываются как недоступные; пересылка продолжается. Чтение результатов не запускает дополнительные проверки. Создание настроек агента и посетителя сохраняет локальные разрешения каталогов и целей: проверьте и запустите файл на агенте, предварительно выполнив там `--check`. Команды служб и обновления предоставляются для проверки и не выполняются консолью.
