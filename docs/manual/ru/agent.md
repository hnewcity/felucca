# Модуль felucca-agent

На этой странице рассматриваются развёртывание и настройка `felucca-agent`: подключение к
серверу, доверие к сертификатам, переподключения, организация исходящей сети, вышестоящие
прокси, журналирование и несколько экземпляров.

## Минимальная конфигурация

```toml
server = "bridge.example.com:14028"
key_id = "agent-1"
vkey = "change-me-to-a-long-random-string"
transport = "tls"          # tcp | tls | ws | wss | quic | kcp

[trust]
mode = "pinned"
fingerprint = "0000...0000"   # from the server's --fingerprint

[[tunnel]]
mode = "tcp"
port = 8080
[[tunnel.backend]]
addr = "127.0.0.1:3000"
```

Поле `server` принимает имя хоста или IP-адрес вместе с портом. Значение `key_id` должно
совпадать с именем таблицы `[client.<key_id>]` на сервере.

## Транспорт и доверие

Поле `transport` принимает значения `tcp`, `tls`, `ws`, `wss`, `quic` и `kcp`. Для публичных
мостов предпочтительны TLS/WSS/QUIC: `tcp` и `ws` аутентифицируют собеседника, но не шифруют
трафик, поэтому это транспорты открытого текста, которые выбирают осознанно.

Таблица `[trust]` определяет, как проверяется сертификат сервера:

| `mode` | Поведение |
| --- | --- |
| `webpki` | Обычная проверка по публичным центрам сертификации. Поле `fingerprint` задавать не нужно |
| `pinned` | Закрепляет SHA-256 всего сертификата. Подпись рукопожатия проверяется, а имя домена и срок действия — нет. Обновляйте отпечаток при каждой смене сертификата |
| `insecure` | Только для временной диагностики |

После того как вы зададите фиксированный PEM в `bridge.tls`, получите отпечаток командой
`felucca-server --fingerprint`.

## Подключение и переподключение

| Поле | По умолчанию | Примечания |
| --- | --- | --- |
| `reconnect_min` | — | Нижняя граница запаса при увеличении интервала переподключения |
| `reconnect_max` | — | Верхняя граница запаса при увеличении интервала |
| `dial_timeout` | — | Время ожидания одной попытки установки соединения |
| `max_connections` | — | Ограничение числа соединений для этого агента |

Агент переподключается автоматически после разрыва; сервер заново регистрирует слушатели и
состояние сеанса. Счётчики трафика сохраняются при переподключениях.

## Исходящая сеть

```toml
[network]
local_ip = "192.0.2.10"
forward_local_ip = true
dns = ["192.0.2.53:53"]

[network.proxy]
kind = "socks5"           # http (CONNECT) | socks5
server = "192.0.2.20:1080"
remote_dns = true
[network.proxy.auth]
username = "edge"
password = "replace-with-proxy-password"
```

| Поле | Примечания |
| --- | --- |
| `local_ip` | Привязывает IP-адрес исходящего трафика моста. Это должен быть адрес, который действительно принадлежит этой машине; имена интерфейсов не принимаются |
| `forward_local_ip` | Этот адрес используют также соединения с бэкендами и пробы работоспособности. По умолчанию его привязывает только мост |
| `dns` | Обычный список `IP:port`. Если он пуст, применяется системный преобразователь имён. Ответы кэшируются по TTL, поддерживаются записи A/AAAA и переход на TCP при обрезке по UDP |
| `network.proxy` | Вышестоящий прокси. Он обслуживает только TCP/TLS/WS/WSS моста и не пересылает запросы к бэкендам и UDP-пакеты NTP |

ACL целей проверяются по **IP-адресу, который фактически вернуло разрешение имени**, и агент
затем подключается именно к этим проверенным адресам, поэтому повторное разрешение не позволит
обойти проверку. Адрес `local_ip` и адреса DNS должны относиться к одному семейству адресов.
Мост через QUIC/KCP не может одновременно использовать вышестоящий прокси поверх TCP.

## Синхронизация времени

И сервер, и агент принимают секцию `[ntp]` для калибровки времени аутентификации моста:

```toml
[ntp]
server = "time.example.com:123"
interval = "5m"
timeout = "5s"
max_offset = "24h"
```

По умолчанию ни один сервер времени не опрашивается. Значение `interval` может находиться в
диапазоне от 1 секунды до 24 часов. Значение `timeout` должно быть положительным, не больше
30 секунд и меньше `interval`. Значение `max_offset` должно быть положительным и не больше
7 суток. Если первый запрос завершился ошибкой, используется системное время. Калибровка не
меняет системные часы, поэтому срок действия сертификатов TLS и истечение квот по-прежнему
определяются системным временем. Источнику NTP нужно доверять: простой SNTP не
аутентифицирует источник времени.

Запросы NTP от агента используют его собственные настройки DNS и исходящего трафика; сервер
использует системный DNS и стандартный исходящий трафик.

## Приём централизованной конфигурации

```toml
[remote]
enabled = true

[remote.target_policy]
allow = ["10.0.0.0/8"]
ports = [80, 443]

[remote.file_root.documents]
path = "/srv/documents"
read_only = true
```

Флаг `remote.enabled` нужно задать явно. Основное соединение должно использовать TLS/WSS/QUIC
с проверенным сертификатом; соединение открытого текста не может запрашивать конфигурацию.
Секция `remote.target_policy` — это жёсткая граница на самой машине агента; она пересекается с
каждым рассылаемым туннелем. Секция `remote.file_root` заранее объявляет именованные
возможности доступа к каталогам, и сервер может рассылать пути только внутри этих имён
возможностей. Каталог, доступный только для чтения, нельзя сделать доступным для записи через
удалённую конфигурацию. См. [Интерфейс управления и централизованная конфигурация](management.md).

При `remote.console_scope = true` поле `target_policy` в серверной секции `[managed.<client-id>]` заменяет локальное `remote.target_policy`, поэтому диапазон можно менять в редакторе устройства в консоли; если сервер его не задаёт, действует локальный диапазон. Без этого параметра рассылаемая конфигурация с `target_policy` отклоняется. Возможности доступа к каталогам всегда определяются только локально. Пакеты подключения, созданные консолью, включают этот параметр.

## Журналирование

```sh
felucca-agent -c agent.toml --log-level debug --log-file /data/agent.log --log-json
```

Задание `--log-file` включает ротацию с файлами по 10 MiB и 5 архивными копиями по умолчанию.
Записи дописываются в журнальные файлы, а выдача в stderr сохраняется. Родительский каталог
должен уже существовать. Флаги `--log-max-bytes`, `--log-backups` и `--log-rotate-interval`
требуют `--log-file`. Необработанные секреты никогда не попадают в журнал.

## Несколько экземпляров

```sh
felucca-agent --config office.toml --config home.json --check
felucca-agent --config office.toml --config home.json
```

Один процесс поддерживает до 32 экземпляров. См. [Источники конфигурации и CLI](configuration.md).
