# Модуль felucca-server

На этой странице описаны развёртывание и настройка `felucca-server`: слушатели моста,
таблица клиентов, HTTP-вход, авторизация портов, слушатель интерфейса управления, локальные
сервисы сервера и переключатели внешних платформ.

## Минимальная конфигурация

```toml
[bridge]
bind = "0.0.0.0:14028"
ws_path = "/ws"
tls = { cert = "conf/bridge.pem", key = "conf/bridge.key" }

[client.agent-1]
vkey = "change-me-to-a-long-random-string"

[log]
level = "info"
```

Если `bridge.tls` не задан и включено хранение конфигурации (включая `--init` или консоль), сервер сохраняет идентичность рядом со снимком в `<snapshot>.identity.json`. Сохраняйте этот файл при перезапуске и резервном копировании. Без хранилища идентичность временная. `--fingerprint` читает явно заданные PEM-файлы; автоматически созданный отпечаток виден в работающей консоли и журнале запуска.

```sh
target/release/felucca-server --config conf/server.toml --check
target/release/felucca-server --config conf/server.toml
```

## Слушатели моста

| Поле | По умолчанию | Примечания |
| --- | --- | --- |
| `bridge.bind` | `0.0.0.0:14028` | TCP, TLS, WS и WSS делят один сокет и различаются по характеристикам рукопожатия |
| `bridge.quic_bind` | нет | Независимый UDP-адрес; может использовать тот же номер порта, что и TCP |
| `bridge.kcp_bind` | нет | UDP-слушатель KCP; не может разделять UDP-порт с QUIC/HTTP3 |
| `bridge.ws_path` | `/ws` | Путь WS/WSS. Обе стороны должны совпадать; обновления по другим путям отклоняются |
| `bridge.tls` | нет | `{ cert, key }`. Если не задан, генерируется временный сертификат |
| `bridge.cert_reload_interval` | `30s` | Интервал перезагрузки PEM. Перезагрузка не прерывает существующие соединения |
| `bridge.proxy_accept` | выкл. | Принимает заголовки PROXY от доверенных балансировщиков нагрузки |
| `[bridge.mux]` | см. ниже | Окна и бюджеты mux |
| `[bridge.kcp]` | см. ниже | Параметры KCP |

Раздел `[bridge.mux]` предоставляет поля `initial_stream_window`, `max_stream_window`,
`max_session_window`, `max_send_queue`, `max_control_queue`, `max_streams`, `accept_backlog`
и `open_timeout`. На стороне агента есть соответствующий раздел `[mux]` с теми же полями.
Собственные потоки QUIC эти настройки не используют.

Раздел `[bridge.kcp]` принимает поля `mtu`, `send_window`, `receive_window`, `interval_ms`,
`nodelay`, `fast_resend`, `congestion_control`, `session_timeout`, `data_shards`,
`parity_shards` и `max_sessions`. По умолчанию используется FEC из 10 данных и 3 контрольных
фрагментов, поэтому можно потерять любые 3 из 13 пакетов группы и всё равно восстановить
данные. Обе стороны должны использовать одинаковые MTU и одинаковое число фрагментов.

## Таблица клиентов

У каждого агента одна таблица `[client.<key_id>]`. Значение `key_id` — это имя агента на
сервере, и собственное `key_id` агента должно совпадать с именем таблицы.

| Поле | Примечания |
| --- | --- |
| `vkey` | Обязательно. Общий секрет для взаимной HMAC-аутентификации. За его длину и случайность отвечаете вы |
| `remark` | Примечание, показывается на странице управления |
| `user` | Связывает таблицу `[user.<name>]`; используется для многоуровневых квот, ACL и прав арендатора |
| `enabled` | Значение `false` постоянно отключает этого клиента и разрывает его соединение |
| `allow_config_push` | Может ли этот агент регистрировать туннели. Задайте `true`, чтобы рассылать конфигурацию `[[managed.<id>.tunnel]]` |
| `max_tunnels` | Лимит числа туннелей для этого агента |
| `max_connections` | Лимит числа соединений для этого агента |
| `rate_limit` | Ограничение в байтах в секунду, общее для всех туннелей и обоих направлений |
| `acl_mode` / `acl_rules` | ACL источника для доступа к публичной точке входа этого клиента |
| `quota` | `{ flow_limit, expires_at }`, в байтах и в секундах Unix |

Новое соединение с тем же `key_id` заменяет старое; старые слушатели останавливаются и
освобождаются до повторной привязки портов. Счётчики трафика и ограничители пропускной
способности сохраняются при переподключениях внутри одного процесса.

## Авторизация портов

Поле `allowed_ports` является полем верхнего уровня и **должно находиться перед первым
заголовком TOML-таблицы**:

```toml
allowed_ports = [8080, { from = 9000, to = 9100 }]
```

Пустой список разрешает все TCP/UDP-порты выше 1024. Поля `max_tunnels` и `max_connections` —
это глобальные ограничения верхнего уровня, которые учитываются отдельно для каждого агента.

## HTTP-вход

```toml
[http]
bind = "0.0.0.0:8080"
tls_bind = "0.0.0.0:8443"      # set to "" to disable HTTPS
http3_bind = "0.0.0.0:8443"    # optional, HTTP/3 UDP ingress
forwarded_headers = true
response_timeout = "100s"
cert_reload_interval = "30s"

[http.certificates."app.example.com"]
cert = "conf/app.pem"
key = "conf/app.key"

[http.default_tls]
cert = "conf/default.pem"
key = "conf/default.key"

[http.proxy_accept]
mode = "required"
trusted = ["192.0.2.10", "2001:db8:1::/64"]
```

Полное описание использования см. в разделах [Обратный прокси HTTP/HTTPS](http-services.md)
и [Сертификаты, SNI и ACME](certificates.md).

## Полезные команды

| Команда | Назначение |
| --- | --- |
| `--check` | Проверяет конфигурацию и завершает работу, не занимая порты |
| `--fingerprint` | Выводит SHA-256 сертификата `bridge.tls`. Требует заданного постоянного PEM |
| `--hash-password` | Читает одну строку пароля из stdin и выводит хеш пароля администратора. Пароль должен быть не короче 12 байт |
| `--generate-token` | Выводит Bearer-токен администратора и его хеш для хранения |
| `--runtime-config PATH` | Включает снимок конфигурации времени выполнения |
| `--build-info` | Выводит имя программы, версию, протокол и цель сборки |

## Жизненный цикл

- Сигналы `SIGINT` / `SIGTERM` закрывают слушатели и текущие соединения, после чего
  программа завершается.
- Изменения в стартовых файлах требуют перезапуска процесса. Изменения, внесённые через
  слушатель интерфейса управления, проходят через транзакцию снимка конфигурации времени
  выполнения, которая прерывает пересылаемые соединения, но агент затем переподключается.
- Изменение привязки интерфейса управления, путей к файлам сертификатов, публичного origin
  или пути к файлу состояния **требует перезапуска процесса**.
- Счётчики трафика сохраняются при переподключениях агентов. При перезапуске сервера они
  сохраняются только тогда, когда настроена секция `[state]`.
