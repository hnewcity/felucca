# Быстрый старт

Используйте свой публичный Server или запросите команду подключения у его оператора. Заранее создавать сертификат, редактировать конфигурацию или устанавливать агент не требуется.

## Подключение устройства одной командой

1. В разделе **Устройства → Подключить устройство** введите имя. По умолчанию доступны это устройство, локальная сеть и Интернет. Чтобы ограничить доступ, откройте **Дополнительные настройки: права доступа** и выберите это устройство, локальную сеть или свой диапазон.
2. Скопируйте команду и выполните её в Terminal (macOS/Linux) или PowerShell (Windows) на устройстве. Она определит процессор, загрузит подходящий клиент и проверит контрольную сумму.
3. Оставьте окно открытым. После подключения выберите **Добавить службу**, укажите локальный адрес и используйте опубликованный адрес. При разрыве соединение восстанавливается автоматически.
4. Для частного доступа создайте принимающее устройство и выполните его команду на другом компьютере. Получателю не нужен вход в консоль управления.

Команда содержит учётные данные устройства: передавайте её только нужному пользователю. Для повторного подключения закройте прежнее окно и выполните ту же команду. На сервере должен быть пакет для ОС устройства. ZIP, права на папки и расширенные настройки остаются необязательными.

## Запуск своего Server

С программами из дистрибутива выполните инициализацию один раз в доступном для записи каталоге:

```sh
./felucca-server --init
```

Команда создаёт конфигурацию, показывает случайный пароль root и запускает сервер. Откройте указанный адрес. Сохраняйте `felucca-server.toml` и весь каталог `felucca-server.data/` при обновлении или резервном копировании. Затем запускайте без `--init`:

```sh
./felucca-server
```

Для публичного развёртывания используйте `--init --admin-url https://console.example.com` за HTTPS-прокси, передающим запросы на `127.0.0.1:8990` с сохранением Host. Прямой HTTP-адрес открывает соответствующий порт публично; для публичного доступа используйте HTTPS. Устройствам нужен доступ к мосту TCP 9001, посетителям — к опубликованному порту службы. См. [развёртывание и распространение клиентов](../../management.md).

## Предварительные требования

| Требование | Подробности |
| --- | --- |
| Rust 1.88 или новее | Для сборки; этот репозиторий проверен на Rust 1.98.1 |
| Python 3 + OpenSSL | Нужны только локальному демонстрационному скрипту `scripts/demo-local.py` |
| Хост с публичным IP-адресом | Запускает `felucca-server` |
| Хост в частной сети | Запускает `felucca-agent` с сервисом, который нужно открыть наружу |
| Право привязки локальных TCP/UDP | Нужно для проверки; правилами межсетевого экрана управляет тот, кто разворачивает систему |

Felucca не устанавливает системные сервисы и не меняет правила межсетевого экрана.

## Вариант 1 — локальная демонстрация

Если вы хотите просто увидеть работу на собственной машине (страница управления и проброс
портов), без публичной сети:

```sh
python3 scripts/demo-local.py
```

Скрипт инкрементально собирает отладочные бинарники, генерирует сертификат и случайные
учётные данные, запускает тестовый сайт, сервер и агент, проверяет реальную пересылку
трафика, а затем сам открывает демонстрационную страницу. В терминале выводятся адрес
интерфейса управления, учётная запись и пароль. Нажмите `Ctrl+C`, чтобы остановить все
демонстрационные сервисы.

Каждый слушатель привязывается только к `127.0.0.1`, а если порт по умолчанию уже занят,
автоматически выбирается свободный. Каждый запуск хранит свою конфигурацию, данные для
входа и журналы в собственном каталоге `target/local-demo/run-*`.

| Флаг | Действие |
| --- | --- |
| `--no-open` | Не открывать браузер автоматически |
| `--no-build` | Пропустить сборку, если бинарники уже собраны |

## Вариант 2 — сборка

```sh
npm --prefix apps/admin ci
npm --prefix apps/admin run build
sh scripts/cargo-external.sh build --release --locked -p felucca-cli --bins
```

В результате получаются `target/release/felucca-server` и `target/release/felucca-agent`.
Скрипт `scripts/cargo-external.sh` размещает кэш Cargo на том диске, где находится рабочее
пространство. Если места на диске достаточно, можно вызывать `cargo` и напрямую.

## Вариант 3 — первый туннель вручную

### 1. Сгенерируйте сертификат моста

Сертификат моста создаётся один раз, а закрытый ключ нужно сохранить:

```sh
mkdir -p conf
umask 077
openssl req -x509 -newkey rsa:2048 -nodes -days 365 \
  -subj '/CN=felucca' -keyout conf/bridge.key -out conf/bridge.pem
cp examples/felucca-server.toml conf/server.local.toml
cp examples/felucca-agent.toml conf/agent.local.toml
```

### 2. Задайте общий ключ

Значение `vkey` в обоих файлах должно быть одной и той же случайной строкой:

```sh
openssl rand -hex 32
```

Запишите его в `[client.agent-1].vkey` файла `conf/server.local.toml` и в `vkey` файла
`conf/agent.local.toml`. Значение `key_id` агента должно совпадать с записью таблицы
`[client.<id>]` на сервере. Замените значение `server` в конфигурации агента на доступный
адрес хоста сервера.

### 3. Считайте отпечаток сертификата

```sh
target/release/felucca-server --config conf/server.local.toml --fingerprint
```

Поместите выведенный отпечаток SHA-256 в поле `[trust].fingerprint` агента. Затем проверьте
оба файла:

```sh
target/release/felucca-server --config conf/server.local.toml --check
target/release/felucca-agent --config conf/agent.local.toml --check
```

### 4. Запустите обе программы

Выполните по одной команде в каждом из двух терминалов:

```sh
target/release/felucca-server --config conf/server.local.toml
```

```sh
target/release/felucca-agent --config conf/agent.local.toml
```

### 5. Проверьте результат

Пример конфигурации пересылает TCP-порт `8080` на сервере на `127.0.0.1:3000` на машине
агента. Запустите на машине агента сервис, который слушает порт 3000, а затем обратитесь к
порту 8080 на сервере.
