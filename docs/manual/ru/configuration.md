# Источники конфигурации и CLI

На этой странице описано, откуда берётся конфигурация, как она передаётся, какие переменные
окружения действуют и как выполнить проверку, не запуская программу. Значения отдельных
полей описаны в руководствах по модулям.

## Файлы конфигурации

Обе программы принимают TOML и JSON. Относительные пути разрешаются относительно рабочего
каталога процесса, поэтому и `--workdir`, и стартовый каталог в systemd/launchd имеют
значение.

```sh
felucca-server --config /srv/felucca/server.toml
felucca-agent  --config /srv/felucca/agent.toml
```

Без `--config` программы читают `felucca-server.toml` / `felucca-agent.toml` из рабочего
каталога. Флаг `-c` — короткая форма `--config`; агент дополнительно принимает псевдоним
`--launch`.

Вся конфигурация обрабатывается с `deny_unknown_fields`: неизвестное поле является ошибкой и
никогда не игнорируется молча.

## Допустимые источники

Флаг `--config` принимает четыре формы:

| Форма | Пример | Подробности |
| --- | --- | --- |
| Локальный файл | `conf/server.toml` | TOML или JSON |
| HTTP(S) URL | `https://cfg.example/edge.json` | Ожидание не более 15 секунд и обязательный код 200; перенаправления не прослеживаются, сжатые ответы не принимаются; в URL не допускаются userinfo и fragment, а параметры запроса могут нести подписанный адрес загрузки |
| Встроенный JSON | `'{"bridge":{"bind":"0.0.0.0:14028"}}'` | Передаёт объект JSON напрямую |
| base64 | `base64:eyJicmlkZ2Ui...` | Стандартный base64 или base64url без padding |

Размер одной конфигурации не может превышать 4 MiB. Флаг `--config-token-env NAME` читает
Bearer-токен из переменной окружения для приватных адресов загрузки; учётные данные никогда
не попадают в журнал. URL, токен и встроенное содержимое никогда не выводятся в качестве
имени источника конфигурации.

В удалённой конфигурации пути к сертификатам, геоданным и файловым корням по-прежнему
указывают на пути на **машине агента**.

## URI запуска агента

`felucca-agent` также принимает короткий URI. Сам по себе он только подключает, а для локальных туннелей по-прежнему нужны TOML/JSON; с `remote=1` туннели и диапазон доступа приходят от сервера, и хватает одной команды:

```sh
felucca-agent --config 'felucca://bridge.example.com:14028?key_id=edge&vkey=YOUR_KEY&transport=tls'
felucca-agent --config 'felucca://bridge.example.com:14028?key_id=edge&vkey=YOUR_KEY&fingerprint=SHA256_HEX&remote=1'
```

| Поле | Обязательно | Подробности |
| --- | --- | --- |
| Порт | Да | Должен быть ненулевым |
| `vkey` | Да | Общий ключ; значение должно быть закодировано в процентах |
| `key_id` | Нет | Если не задано, используется идентичность по умолчанию |
| `transport` | Нет | `tcp`/`tls`/`ws`/`wss`/`quic`/`kcp` |
| `fingerprint` | Нет | Включает проверку SHA-256 закреплённого сертификата |
| `ws_path` | Нет | Путь WebSocket |
| `remote` | Нет | `1` передаёт сервисы и диапазон доступа серверу: включает `remote.enabled` и `remote.console_scope`; до получения диапазона от сервера разрешены только локальные адреса |

Неизвестные и повторяющиеся поля являются ошибками.

## Несколько экземпляров агента

Флаг `--config` можно повторять, до 32 экземпляров в одном процессе:

```sh
felucca-agent --config edge-a.toml --config edge-b.json
felucca-agent --config 'https://cfg.example/edge.json' --config-token-env CONFIG_TOKEN
```

У каждого экземпляра свои соединения, задержка переподключения, маршруты, пробы и лимиты
соединений. Вся конфигурация сначала проверяется и инициализируется, и только затем
начинается подключение; повторяющаяся комбинация `server` + `key_id` является ошибкой. Если
один сервер недоступен, остальные экземпляры продолжают работать, а сигнал на завершение
закрывает все экземпляры.

## Подстановка переменных окружения

По умолчанию выключена. Задайте `--expand-env` (или `FELUCCA_EXPAND_ENV=true`), и
разрешённые строковые значения будут раскрыты:

```toml
server = "${FELUCCA_SERVER:-127.0.0.1:9001}"
key_id = "${FELUCCA_KEY_ID:-agent-1}"
vkey = "${FELUCCA_VKEY}"
```

Запись `${VAR}` требует, чтобы переменная существовала. Запись `${VAR:-default}` использует
значение по умолчанию, если переменная отсутствует или пуста. Запись `$$` — это литеральный
`$`. Подстановка выполняется один раз, не затрагивает имена полей и не преобразует строки в
числа. Результат больше 4 MiB отклоняется.

## Снимок конфигурации времени выполнения

```sh
felucca-server --config bootstrap.toml --runtime-config conf/runtime.json
```

Путь можно также задать через `FELUCCA_RUNTIME_CONFIG`. После первого успешного запуска
нормализованная конфигурация сохраняется атомарно, и последующие запуски сначала читают
снимок. Флаги `--check` и `--fingerprint` читают тот же снимок. Если файл повреждён, запуск
завершается ошибкой и не выполняет откат к стартовому файлу. **Не** указывайте тот же путь,
что и у файла трафика `[state].path`.

Снимок имеет размер не более 16 MiB и содержит настоящие секреты; в Unix новый файл получает
права 0600, а новый каталог — 0700, а файловая блокировка не позволяет другому демону
использовать его одновременно.

Изменение конфигурации из интерфейса управления использует тот же механизм — см. раздел
[Управление и централизованная конфигурация](management.md).

## Проверка и журналирование

```sh
felucca-server --config conf/server.toml --check
felucca-agent  --config conf/agent.toml  --check
```

Флаг `--check` проверяет структуру TOML/JSON, ограничения полей, порты, ACL и геоданные. Он
**не** подключается к бэкендам, **не** проверяет публичный DNS и **не** анализирует
содержимое файлов сертификатов. Содержимое сертификатов и конфликты привязки портов
проверяются в момент запуска.

Флаги журналирования агента:

```sh
felucca-agent -c agent.toml --log-level info \
  --log-file /data/agent.log --log-json \
  --log-max-bytes 10485760 --log-backups 5 --log-rotate-interval 24h
```

Переменная `RUST_LOG` переопределяет уровень журналирования в обеих программах.
Журналирование сервера настраивается в таблице `[log]`, и для его изменения нужен
перезапуск.

## Переменные окружения

| Переменная | Действие |
| --- | --- |
| `FELUCCA_CONFIG` | То же, что и `--config` (у агента можно повторять) |
| `FELUCCA_RUNTIME_CONFIG` | То же, что и `--runtime-config` у сервера |
| `FELUCCA_EXPAND_ENV` | То же, что и `--expand-env` |
| `FELUCCA_CONFIG_TOKEN_ENV` | Имя переменной, содержащей Bearer-токен удалённой конфигурации |
| `RUST_LOG` | Переопределяет уровень фильтрации журнала |
