# Сертификаты, SNI и ACME

На этой странице описаны три вида сертификатов: сертификат моста, сертификаты статических
веб-сайтов и сертификаты, которые выдаются и обновляются автоматически через ACME.

## Сертификат моста

```toml
[bridge]
bind = "0.0.0.0:14028"
tls = { cert = "conf/bridge.pem", key = "conf/bridge.key" }
cert_reload_interval = "30s"
```

Если `bridge.tls` не задан и включено хранение конфигурации (включая `--init` или консоль), сервер сохраняет идентичность рядом со снимком в `<snapshot>.identity.json`. Сохраняйте этот файл при перезапуске и резервном копировании. Без хранилища идентичность временная. `--fingerprint` читает явно заданные PEM-файлы; автоматически созданный отпечаток виден в работающей консоли и журнале запуска.

PEM-файлы перечитываются с интервалом `cert_reload_interval` (по умолчанию 30 секунд). Новые
соединения TLS/WSS и QUIC получают новый сертификат, а существующие соединения не прерываются.
Если обновление сертификата или ключа выполнено не полностью, сохраняется предыдущее значение.
Агент с режимом доверия `pinned` должен обновить отпечаток до следующего переподключения; агенту,
который проверяет сертификат по корректному центру сертификации, закреплять конкретный
сертификат не нужно.

```sh
target/release/felucca-server --config conf/server.toml --fingerprint
```

На стороне агента у вас есть два варианта:

```toml
[trust]
mode = "pinned"
fingerprint = "<from --fingerprint>"

[trust]
mode = "webpki"        # CA-issued bridge certificate
```

## Сертификаты веб-сайтов

```toml
[http.certificates."app.example.com"]
cert = "conf/app.pem"
key = "conf/app.key"

[http.certificates."*.example.com"]
cert = "conf/wildcard.pem"
key = "conf/wildcard.key"

[http.default_tls]
cert = "conf/default.pem"
key = "conf/default.key"
```

Точное совпадение имеет приоритет над маской, а маска — над `default_tls`. Если совпадений нет,
рукопожатие отклоняется. Расхождение между SNI и HTTP-заголовком Host даёт 421. Статические
сертификаты перечитываются каждые 30 секунд по умолчанию; интервал можно изменить через
`http.cert_reload_interval`. Сертификат заменяется только после того, как он совпал со своим
закрытым ключом, а при ошибке остаётся прежний сертификат.

HTTP/3 и HTTP/HTTPS используют один и тот же резолвер SNI, включая обновление через ACME и
горячую перезагрузку статических PEM-файлов.

## Выдача через ACME

```toml
[http.acme]
email = "admin@example.com"
accept_tos = true
challenge = "http-01"          # http-01 | tls-alpn-01
cache_dir = "state/acme"
staging = false
domains = ["app.example.com"]
```

| Поле | Описание |
| --- | --- |
| `accept_tos` | Устанавливайте в `true` только после принятия условий центра сертификации |
| `challenge` | `http-01` требует публичный TCP 80 до `http.bind`. `tls-alpn-01` требует публичный TCP 443 прямо до `http.tls_bind`, и в этом случае `http.bind` может быть закрыт |
| `staging` | Сначала проверьте связность на стенде; это фиксирует стенд Let's Encrypt |
| `directory` | Указывает на другой центр сертификации; по умолчанию — рабочее окружение Let's Encrypt |
| `cache_dir` | Каталог для учётной записи и кэша сертификатов. **Сохраняйте и защищайте его** |
| `domains` | Явно ограничивает список выдаваемых имён. Когда он пуст, имена выводятся каждую минуту из зарегистрированных точных доменов, а маски пропускаются |

Учётная запись хранится в `account.json`, а цепочка сертификатов и закрытый ключ каждого домена
находятся вместе в одном JSON-файле, который заменяется атомарно. В Unix-системах файлы имеют
режим 0600, а новые каталоги кэша — 0700. Сертификаты восстанавливаются из кэша при запуске.
Момент обновления вычисляется по фактическому сроку действия сертификата с упреждением не более
трети этого срока. Проверки выполняются каждую минуту, при ошибках повторная попытка выполняется
через час, а до успешного обновления продолжает использоваться старый сертификат. Успешная выдача
подставляется на горячую и не прерывает существующие TLS-соединения.

**ACME управляет только сертификатами обратного прокси HTTP/HTTPS. Он не меняет сертификат
моста и не меняет закреплённый отпечаток агента.**

### EAB и ZeroSSL

```toml
[http.acme.eab]
key_id = "issued-by-your-ca"
hmac_key = "base64url-key-issued-by-your-ca"
```

ZeroSSL можно использовать с EAB, заданным вручную, или переключиться в режим ключа API:

```toml
[http.acme]
directory = "https://acme.zerossl.com/v2/DV90"
staging = false
zerossl_api_key = "your-account-key"
```

Режим ключа API получает EAB при первой регистрации учётной записи, а затем выдаёт сертификаты
через ACME. **Одновременно с ним нельзя настроить EAB `eab` вручную.** После появления кэша
учётной записи новый EAB не запрашивается. Ключ API и секреты из ответов не записываются в
сообщения об ошибках.

## Примечания по развёртыванию

- Ни один вызов ACME **не поддерживает сертификаты с маской**. Для имён с маской используйте
  статические сертификаты, выданные извне.
- Когда ваше приложение слушает порты 8080/8443, отобразите порты 80/443 на них извне.
- До успешной выдачи рукопожатие TLS для этого домена может завершаться ошибкой; HTTP-01
  по-прежнему обеспечивает проверку.
- Завершающий TLS прокси перед сервером должен пересылать рукопожатие вызова без изменений и
  возвращать сертификат вызова только для значений ALPN, содержащих `acme-tls/1`.
- Используйте новый `cache_dir`, когда меняете центр сертификации или переключаетесь между
  стендом и рабочим окружением.
- В репозитории выполняются реальные потоки CSR и вызовов против локального имитируемого центра
  сертификации. Реальную выдачу публичным центром сертификации всё равно нужно проверить в
  собственной доменной среде.
