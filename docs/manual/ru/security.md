# Управление доступом, квоты и кодирование потока

На этой странице собраны связанные с безопасностью параметры: ACL источника, ACL целей,
GeoIP/GeoSite, многоуровневые квоты и ограничения скорости, снимки трафика, а также необязательное
сжатие и шифрование для каждого туннеля.

## ACL источника

```toml
[client.agent-1]
acl_mode = "allow"                 # off | allow | deny
acl_rules = "203.0.113.0/24, 2001:db8::/32"
```

Правила — это записи IP/CIDR, разделённые запятыми или переводами строк. Поля `acl_mode`/`acl_rules`
верхнего уровня сервера, секции `[user.<name>]`, `[client.<id>]` и правила туннеля **пересекаются**;
клиент связывает себя с пользователем в собственной конфигурации через `user = "<name>"`, и агент не
может изменить эту связь.

Эти правила применяются к клиентам, которые доходят до публичной точки входа, и **не используются
для отказа в адресе моста агента** — идентичность моста проверяется по vkey. Правила действуют на
IP-адрес источника клиентов, обращающихся к прокси, а не на адрес цели.

ACL источника поддерживают GeoIP. Атрибут `acl_rules` также можно задать в секциях `[[tunnel]]`,
`[local.<name>]` и `[[visitor]]`.

## Политика целей

Исполняется на стороне агента и применяется к фиксированным бэкендам, проверкам работоспособности и
целям прямого прокси:

```toml
[tunnel.target_policy]
allow = ["domain:api.example.com", "suffix:example.net", 'regex:^db[0-9]+\.internal$']
deny = ["127.0.0.0/8", "::1", "169.254.0.0/16"]
ports = [80, 443]
```

| Элемент       | Описание                                                                        |
| ---         | ---                                                                              |
| Пустой `allow` | Ограничений на допустимые цели нет                                             |
| `deny`      | Всегда имеет приоритет                                                           |
| Пустой `ports` | Разрешён любой ненулевой порт                                                   |
| Синтаксис   | IP/CIDR, `domain:`, `suffix:`, `regex:`, `*`                                     |
| Geo         | `geoip:CN`, `geosite:category-ads-all`, `geosite:custom:LOCAL@fast@!ads`         |

Атрибут `@attribute` требует наличия атрибута, атрибут `@!attribute` требует его отсутствия, а
несколько условий пересекаются. Значение `geoip:private` покрывает встроенные диапазоны приватных
адресов IPv4/IPv6, петли, link-local и CGNAT и не требует файла данных. Имя и разрешённый IP-адрес
проверяются вместе; имена нечувствительны к регистру, а конечная точка нормализуется.

Отсутствие файла, отсутствие группы, некорректное регулярное выражение или повреждённый protobuf
**являются ошибкой** и не вырождаются в пустое правило, которое разрешает всё. Данные загружаются при
запуске, поэтому после обновления файла данных перезапустите соответствующий процесс. Каждая сторона
использует свои собственные локально объявленные файлы данных, а удалённая сторона может ссылаться
только на группы и псевдонимы.

## Данные Geo

```toml
[geo]
geoip = "data/geoip.dat"
geosite = "data/geosite.dat"

[geo.extra]
mycorp = "data/mycorp.dat"
```

Укажите на protobuf-файлы `.dat` в формате V2Ray, с путями относительно рабочего каталога процесса.
Префиксы IP используют скомпилированные поиски по диапазонам; домены поддерживают точное совпадение,
совпадение по суффиксу, по ключевому слову и по регулярному выражению.

## Многоуровневые квоты

Секции `[user.<name>.limits]`, `[tunnel.options.limits]` и
`[http.host_limit."<domain pattern>"]` принимают одинаковые поля:

```toml
max_connections = 20
rate_limit = 1048576
quota = { flow_limit = 1073741824, expires_at = 1893456000 }
```

Единицы измерения трафика и скорости — байты, а значение `expires_at` задаётся в секундах Unix.
Пропуск поля означает отсутствие ограничения; нулевая скорость означает отсутствие ограничения, а
нулевое число соединений явно блокирует новые соединения. Несколько клиентов одного пользователя,
несколько соединений одного туннеля и несколько путей одного домена делят собственные счётчики и
ограничения.

Несколько уровней скорости применяются одновременно, а время ожидания выбирается по **самому
строгому уровню**; при неудачном запросе слота соединения возвращаются слоты, выданные более ранними
уровнями. Ограничения домена в HTTP выбираются по первоначальным Host/SNI, точный домен имеет
приоритет над маской, и на них не влияет перезапись Host на бэкенде. Подсчёт HTTP-соединений покрывает
фактические соединения с бэкендами; несколько HTTP/2-запросов могут переиспользовать одно соединение.

TCP, HTTP, SNI и UDP обновляют счётчики каждого уровня. TCP проверяется и ограничивается по скорости
блоками по 16 KiB, а UDP обрабатывается по датаграммам. Трафик, находящийся в полёте при
одновременных передачах, может несколько превысить итоговую квоту, поэтому это **не** точное
побайтовое отсечение. HTTP учитывает байты протокола бэкенда, включая заголовки и накладные расходы
протокола; UDP учитывает только полезную нагрузку. Квота разрывает соединения, которые уже передают
данные, а счётчики не предназначены для строгого биллинга.

## Снимки трафика

```toml
[state]
path = "data/traffic.json"
save_interval = "5s"
```

После включения снимок атомарно заменяется с указанным интервалом, а окончательные счётчики
сохраняются при обычном завершении работы и после окончания соединений. Снимок включает отключённые
ресурсы, поэтому они по-прежнему учитываются в квотах после перезапуска сервера; аварийное падение
может потерять данные последнего интервала сохранения. Один снимок может записываться только одним
сервером. Повреждённый снимок или снимок неизвестной версии не дают серверу запуститься, а
первоначальный файл сохраняется.

Это снимок трафика; конфигурация времени выполнения интерфейса управления хранится отдельно в
`admin.state_path` / `--runtime-config`, и эти два пути не должны совпадать. После включения снимков
закрепляйте поле `id` своих туннелей.

## Кодирование потока

```toml
[tunnel.options.payload]
compress = true
encrypt = true
```

| Параметр    | Реализация           | Поведение                                                                                                                          |
| ---         | ---                 | ---                                                                                                                                |
| `compress`  | Snappy              | Работает блоками не более 16 KiB исходных данных и использует сжатый блок, только если он меньше; заявленный размер проверяется до распаковки |
| `encrypt`   | ChaCha20-Poly1305   | Каждый поток обменивается свежим nonce, а vkey агента проверяет идентичность обеих сторон и весь запрос маршрутизации; HKDF выводит два независимых ключа направлений |

При включённом сжатии данные **сжимаются до шифрования**. Заголовки длины, номера
последовательностей и завершающая запись покрываются проверками целостности, а подделка, повтор или
отсутствие завершающей записи закрывают поток данных. Когда настройки двух сторон не совпадают,
согласование отклоняется, без автоматического отката к открытому тексту. Каждое направление
буферизует только одну ограниченную запись.

Этот уровень кодирования находится внутри потока mux/QUIC и не добавляет собственного уровня
мультиплексирования; заголовки PROXY, содержимое HTTP/WebDAV и UDP-датаграммы проходят через одно и
то же кодирование. Квоты трафика и ограничения скорости по-прежнему рассчитываются по **сырым байтам
пересылки**.

Граница безопасности:

- Независимое шифрование защищает информационную часть маршрутизации; регистрация конфигурации и
  управляющие сообщения моста по-прежнему защищаются выбранным транспортом моста, поэтому TLS, WSS или
  QUIC остаются выбором развёртывания по умолчанию.
- Этот уровень PSK **сам по себе не обеспечивает прямой секретности**.
- Сжатие меняет наблюдаемый размер записи; если вам нужно скрыть характеристики сжатия, оставляйте
  `compress = false`.

## Работа с секретами

- Секреты в открытом виде никогда не попадают в журналы; вывод Debug и Display маскируется.
- При сохранении секрет должен оставаться настоящим, а маскирование происходит только при выводе;
  когда вы добавляете поле учётных данных, проверяйте путь маскирования одновременно с ним.
- Снимки конфигурации содержат настоящие секреты, а в Unix новые файлы имеют права 0600, а новые
  каталоги — 0700.
- Не записывайте сам Bearer-токен управления в конфигурацию сервера; записывайте только `token_hash`.
