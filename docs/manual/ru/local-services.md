# Локальные цели сервера и вложенные маршруты

Секция `[local.<name>]` позволяет серверу самому предоставлять сервисы, без агента и без учётных
данных моста. Бэкенды локальных туннелей также могут использовать псевдонимы, ведущие в другой
зарегистрированный туннель, включая туннели на агенте, что складывается во вложенные маршруты.

## Группа локальных сервисов

```toml
[user.office]
[user.office.limits]
max_connections = 100

[local.office]
user = "office"
dial_timeout = "10s"
[local.office.network]
local_ip = "127.0.0.1"
forward_local_ip = true

[[local.office.tunnel]]
id = 1
mode = "tcp"
port = 9001
bind = "127.0.0.1"
backend = [{ addr = "127.0.0.1:3000" }]
[local.office.tunnel.health]
type = "tcp"
interval = "10s"
timeout = "2s"
```

Каждая группа может задавать `user`, `acl_mode`/`acl_rules`, `limits`, `network` и `dial_timeout`,
а также использовать ту же конфигурацию TCP/UDP, HTTP/SNI, прокси, файлов, балансировки нагрузки,
проверок работоспособности и ACL, что и агент. Когда вы запускаете только локальные сервисы,
таблицу клиентов можно не указывать.

Локальная группа записывается как `local.<name>` в реестре и в снимках трафика, и **это
пространство имён нельзя использовать как key_id внешнего агента**. У локальной группы нет моста,
поэтому конфигурация вышестоящего прокси отклоняется. Только `forward_local_ip = true` использует
исходящий IP-адрес для бэкенда. Файловые каталоги, сертификаты и конфигурация бэкендов
подготавливаются при запуске, а конфликт прослушивания приводит к тому, что этот сервис не
запускается.

## Псевдонимы бэкендов

| Адрес | Поведение |
| --- | --- |
| `tunnel://local.office/7` | Входит в точку входа другого зарегистрированного локального туннеля |
| `tunnel://agent-1/7` | Входит в зарегистрированный туннель на подключённом агенте |
| `file://agent-1/7` | То же самое, но требует, чтобы зарегистрированная цель была в режиме `file`; границы каталогов, состояние только для чтения и файловая аутентификация сохраняются |
| `bridge://tcp`, `tls`, `ws`, `wss` | Входит в соответствующую точку входа моста; агенту по-прежнему нужна взаимная аутентификация, а TLS использует сертификат моста |
| `bridge://http` | Входит в точку входа HTTP сервера, где Host, аутентификация сайта и проверки разрешений продолжают выполняться |
| `bridge://web` | Подключается к конечной точке управления, которая аутентифицирует тем же способом |

Номера туннелей должны быть явными и стабильными. Локальная группа с полем `user` может ссылаться
только на цели того же пользователя; группа без поля `user` управляется оператором сервера и может
ссылаться на цели разных пользователей. Псевдонимы `bridge` разрешены только для групп оператора.
Удалённый агент и запросы динамического прокси не могут использовать псевдоним в качестве сетевой
цели.

Псевдонимы не принимают дополнительный `backend.tls`, сетевую проверку работоспособности или ACL
цели точки входа: разрешения обеспечиваются целевыми параметрами каждого прыжка. Псевдоним
HTTPS/SNI может передавать данные TLS напрямую, а целевой сайт завершает или пропускает их дальше.
UDP может вкладываться только в UDP, а остальные режимы используют потоковую точку входа.
Аутентификация прокси SOCKS5/HTTP не пропускается.

## Контроль петель и учёт

- Каждый прыжок сохраняет первоначальный IP-адрес и порт источника и историю маршрутизации.
- Повторяющаяся пара `(client, id)` или более **16 прыжков** немедленно отклоняется.
- Пул HTTP-соединений также изолируется по истории, поэтому повторно использованное соединение не
  может обойти проверку петли.
- Каждый фактически пройденный туннель получает собственный лимит соединений и записывает трафик;
  когда один и тот же пользователь или группа проходит через несколько прыжков, совокупная квота
  также начисляется за каждый прыжок.
- Учёт UDP покрывает только полезную нагрузку сообщения, без внутренних кадров длины.

## Распространённые приёмы

| Сценарий | Как |
| --- | --- |
| Публиковать сервис с хоста сервера | `[local.ops]` + `[[local.ops.tunnel]]` |
| Добавить терминацию TLS перед внутренним сервисом | HTTP-туннель в локальной группе с `tls_mode = "offload"` |
| Добавить ещё одну точку входа поверх внутреннего сервиса, например аутентификацию сайта | Внешняя локальная группа, в которой бэкенд записан как `tunnel://agent-1/7` |
| Переиспользовать аутентификацию конечной точки управления из внутреннего сервиса | Записать бэкенд как `bridge://web` |
