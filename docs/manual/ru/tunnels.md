# Туннели и сопоставления портов

Туннель — базовая единица Felucca: одна публичная точка входа плюс набор бэкендов. На этой
странице описаны общие поля, восемь режимов, пакетные сопоставления портов и протокол PROXY.

## Общие поля туннеля

```toml
[[tunnel]]
id = 1                 # Stable ID; pin it once traffic snapshots are enabled
mode = "tcp"           # Entry protocol
port = 8080            # Port opened on the server
bind = "0.0.0.0"       # IP only, no port attached
remark = "internal web app"
public = true          # false means a private share that does not take a public port
balance = "round_robin"   # Goes inside [[tunnel]], not after [[tunnel.backend]]

[[tunnel.backend]]
addr = "127.0.0.1:3000"
```

Поле `bind` принимает IP-адрес, а не порт; порт берётся из `tunnel.port`. Не указывайте
`bind`, чтобы слушать на всех интерфейсах. Если `id` не задан, назначается доступное
положительное целое число. После включения снимков трафика задавайте `id` явно, а не
полагайтесь на порядок элементов массива.

## Режимы

| `mode` | Поведение точки входа | Источник цели |
| --- | --- | --- |
| `tcp` | Публичный TCP-порт, побайтовая пересылка | `backend` |
| `udp` | Публичный UDP-порт, границы датаграмм сохраняются | `backend` |
| `http` | Переиспользует HTTP-, HTTPS- или HTTP/3-слушатель сервера и маршрутизирует по домену и пути | `backend` |
| `socks5` | Прямой прокси SOCKS5, CONNECT + UDP ASSOCIATE | Задаётся клиентом |
| `httpproxy` | Прямой прокси HTTP, абсолютный URL + CONNECT | Задаётся клиентом |
| `mixedproxy` | Смешанная точка входа, различает SOCKS5 и HTTP по началу запроса | Задаётся клиентом |
| `file` | Раздача файлов и WebDAV | Каталог на хосте агента |
| `transparent` (псевдоним `tcptrans`) | Читает первоначальный адрес назначения из ядра | Ядро |

Туннель `http` **не** открывает отдельный слушатель: его `port` должен совпадать с
`http.bind`, `http.tls_bind` или `http.http3_bind` сервера, и несколько HTTP-туннелей могут
делить один порт. Поле `tunnel.bind` не влияет на маршрутизацию HTTP. HTTP-слушатель
включается на стороне сервера и не ограничен `allowed_ports` агента.

## Пакетные сопоставления портов

Секция `[[mapping]]` поддерживает только TCP и UDP и отображает диапазон портов один к
одному по порядку:

```toml
[[mapping]]
mode = "tcp"
server_ports = "9001-9003,10000"
target_ports = "8001-8003,8080"
target_host = "127.0.0.1"
bind = "0.0.0.0"
```

Число портов с обеих сторон должно быть одинаковым, а повторяющиеся порты сервера
недопустимы. Развёрнутые туннели проверяются вместе с явными записями `[[tunnel]]` и
по-прежнему учитываются в авторизации портов сервера и в лимите числа туннелей. Поле
`target_host` может быть именем домена, адресом IPv4 или адресом IPv6 и не может содержать
порт. Можно также задать `tls`/`trust`, `health`, `acl`, `options` и `target_policy`.

## Поведение UDP

- Для каждой пары IP-источника:порта заводится отдельная ассоциация, которая привязывается
  к одному сокету бэкенда на стороне агента.
- Пустые пакеты и границы датаграмм сохраняются. Максимальный размер датаграммы — 65507
  байт, а допустимый MTU в реальной сети может быть меньше.
- Каждый туннель допускает не более 256 ассоциаций источников, и каждая из них ставит в
  очередь 8 пакетов. При заполнении очереди пакеты отбрасываются, а ассоциация освобождается
  после 60 секунд простоя.
- Датаграммы передаются по надёжному потоку туннеля, **не** через QUIC DATAGRAM, поэтому на
  канале с потерями приходится ждать пересылки.
- Статистика UDP покрывает только полезную нагрузку датаграммы, без внутренних кадров длины.

## Протокол PROXY

Передайте бэкенду первоначальный адрес источника и адрес назначения точки входа:

```toml
[tunnel.options]
proxy_protocol = "v1"     # "off" | "v1" | "v2"
```

Для TCP, HTTP и TLS один заголовок отправляется на каждое соединение с бэкендом. UDP
поддерживает только версию v2, добавляя к каждой датаграмме заголовок DGRAM; пакеты размером
более 65507 байт вместе с заголовком отбрасываются. Бэкенд должен уметь разбирать протокол
PROXY.

На принимающей стороне настройте `proxy_accept` для соответствующего слушателя:

```toml
[http.proxy_accept]
mode = "required"                    # optional | required
trusted = ["192.0.2.10", "2001:db8:1::/64"]
bridge.proxy_accept = { ... }
[tunnel.options.proxy_accept]
mode = "optional"
trusted = ["10.0.0.0/8"]
```

Режим `optional` разрешает прямые подключения без заголовка, а `required` отклоняет
отсутствие заголовка. Когда эта возможность включена, список `trusted` не должен быть
пустым. ACL источника, хеширование по источнику и HTTP-заголовки forwarded используют
проверенный первоначальный адрес. Мост и HTTP-слушатель на одном порту должны быть настроены
с одинаковой политикой. Приём ограничен 5 секундами, а UDP-слушатель не принимает заголовки
PROXY.

## Кодирование потока

```toml
[tunnel.options.payload]
compress = true     # Snappy, default false
encrypt = true      # ChaCha20-Poly1305, default false
```

Это относится к TCP и UDP, к передаче файлов и запросам WebDAV, к потокам данных обратного и
прямого прокси. При включённом сжатии данные сжимаются до шифрования. Каждый поток
обменивается свежим nonce, а из vkey соответствующего агента выводятся два независимых
ключа направлений. Если настройки двух сторон не совпадают, согласование отклоняется —
автоматического отката к открытому тексту нет. Подробности см. в разделе [Управление
доступом, квоты и кодирование потока](security.md).
