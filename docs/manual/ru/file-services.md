# Файловые сервисы и WebDAV

Режим `mode = "file"` раздаёт файлы прямо с агента, без отдельного HTTP-сервера. Он может
использовать выделенный публичный порт либо подключаться к доменному входу HTTP сервера.
Поддерживаются WebDAV, диапазонные запросы, листинги каталогов и аутентификация по учётным
записям.

## Выделенный порт

```toml
[[tunnel]]
id = 100
mode = "file"
port = 9001
bind = "127.0.0.1"

[tunnel.file]
root = "public"
prefix = "/files"
read_only = true
auto_index = true

[tunnel.file.auth.users]
reader = "replace-this-password"
```

| Поле | Описание |
| --- | --- |
| `root` | Обязательное поле. Каталог, который **уже существует** на агенте, относительно рабочего каталога процесса; дескриптор каталога открывается при запуске |
| `prefix` | Префикс URL |
| `read_only` | По умолчанию `true` |
| `auto_index` | Листинги каталогов |
| `auth.users` | Таблица учётных записей; оставьте её пустой для анонимной раздачи |

Запросы не могут выйти за пределы `root` через `..`, абсолютные пути или символические ссылки, и
для целей COPY/MOVE действует то же ограничение. Каталог `root` и конфигурация файловых учётных
записей остаются на агенте и **не** попадают в регистрационное сообщение сервера.

## Доменный вход HTTP

Когда вы задаёте `hosts`, файловые сервисы используют доменный вход HTTP/HTTPS/HTTP3 сервера, и
`port` должен совпадать с этим входом:

```toml
[[tunnel]]
mode = "file"
port = 8443
hosts = ["files.example.com"]

[tunnel.file]
root = "public"
read_only = false
```

В этом режиме можно также задать `tunnel.options.http.backend_http2 = true`. ACL источника, квоты
и ограничения скорости продолжают применяться. Файловый режим **не** настраивает сетевой бэкенд,
политику целевой сети, вывод PROXY или режим необработанного TLS.

## Методы WebDAV

| Режим | Разрешённые методы |
| --- | --- |
| Только чтение (по умолчанию) | `GET`, `HEAD`, `PROPFIND`, `OPTIONS` |
| `read_only = false` | Добавляются `PUT`, `DELETE`, `MKCOL`, `COPY`, `MOVE`, `LOCK`, `UNLOCK` |

Блокировки являются общими для нескольких соединений одного файлового туннеля и снимаются после
перезапуска агента. Поддерживаются диапазонные запросы, условные запросы, листинги каталогов и
`index.html`. Крупные файлы передаются частями и используют противодавление вместо того, чтобы
кэшироваться целиком.

## Файлы в централизованной конфигурации

Когда сервер рассылает файловый сервис, он может ссылаться только на именованную возможность
доступа к каталогу, заранее объявленную на агенте:

```toml
# agent
[remote.file_root.documents]
path = "/srv/documents"
read_only = true
```

```toml
# server: inside [[managed.<client>.tunnel]]
[tunnel.file]
root = "documents/shared"
```

Сервер не может разослать произвольный абсолютный путь. Пути и символические ссылки не могут
выйти за пределы разрешённого каталога, а каталог только для чтения нельзя сделать доступным для
записи через удалённую конфигурацию.

## Контрольный список проверки

1. Команда `felucca-agent --config agent.toml --check` завершается успешно.
2. Команда `curl -i http://127.0.0.1:9001/files/` выводит листинг каталога или возвращает `index.html`.
3. Запрос с заголовком `Range: bytes=0-99` возвращает 206.
4. В режиме только чтения запрос `PUT` возвращает 405.
5. Команда `curl --path-as-is 'http://127.0.0.1:9001/files/../../etc/passwd'` отклоняется.
