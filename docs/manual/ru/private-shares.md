# Приватные общие доступы и посетители

Приватный туннель регистрируется на сервере, но не занимает **ни одного публичного порта**. Другой
агент, посетитель, открывает слушатель на своей машине и обращается к нему по аутентифицированному,
зашифрованному мосту, используя отдельный секрет общего доступа. Так внутренний сервис публикуется
для конкретных узлов, а не для всего интернета.

## Три конфигурации

Каждая из трёх сторон — агент поставщика, агент посетителя и сервер — меняется в одном месте.

### Поставщик: сделать туннель приватным

```toml
[[tunnel]]
id = 1
mode = "tcp"
public = false                 # Omit port and bind
backend = [{ addr = "127.0.0.1:3000" }]

[[tunnel]]
id = 3
mode = "socks5"
public = false
[tunnel.target_policy]
allow = ["127.0.0.0/8", "::1", "10.0.0.0/8"]
```

Поддерживаются входы TCP, UDP, файловые входы и входы прокси. **Доменная маршрутизация HTTP
опирается на HTTP-слушатель и не может быть сделана приватной**; приватный TCP-туннель может
пересылать на любой бэкенд HTTP или HTTPS. Явная установка `port = 0` равносильна приватному
туннелю.

### Сервер: объявить общий доступ

```toml
[share.office-web]
client = "office"              # Node name; for a server-local group use client = "local.<group-name>"
tunnel = 1                     # Stable tunnel ID
secret = "replace-this-shared-secret"
allow_clients = ["laptop"]     # An empty list allows every authenticated node that holds the share secret
direct = true                  # Allow P2P direct connection attempts
```

Длина `secret` составляет 16–4096 байт, и для каждого общего доступа следует использовать свой
секрет. Поля `acl_mode`/`acl_rules` проверяют адрес источника соединений моста посетителей. Одного
секрета общего доступа **недостаточно**, чтобы подключиться в роли анонимного клиента: посетителю
по-прежнему нужны обычная идентичность узла и vkey. Сервер может окончательно отключить узел командой
`client.NAME.enabled = false`.

### Посетитель: слушать локально

```toml
[[visitor]]
name = "office-web"
share = "office-web"
secret = "replace-this-shared-secret"
bind = "127.0.0.1:18080"
mode = "tcp"                   # tcp | udp | socks5
max_connections = 64
udp_idle = "60s"
```

| Поле                | Описание                                                                        |
| ---                  | ---                                                                              |
| `name`               | Уникально в пределах этого агента                                                |
| `share`              | Имя общего доступа на сервере                                                    |
| `mode`               | `tcp`, `udp` или `socks5`                                                        |
| `bind`               | Требует фиксированный порт; привязка выполняется при запуске, а занятый порт сразу даёт ошибку |
| `max_connections`    | 1–4096, по умолчанию 64; TCP-соединения или UDP-сеансы источников                |
| `udp_idle`           | 1 секунда–1 час, по умолчанию 60 секунд; активность в любом направлении продлевает сеанс |
| `acl_mode` / `acl_rules` | Проверяют адрес источника соединений к слушателю посетителя                |
| `target`             | Только для динамических общих доступов, см. ниже                                 |

Все посетители делят с агентом лимит соединений и бюджет очередей UDP в 8 MiB. Посетитель принимает
TLS, WSS или QUIC только с проверенным сертификатом.

Сервер применяет ACL общего доступа, ACL посетителя и маршрутизирующий ACL поставщика к
**фактическому адресу источника моста посетителя**. Необработанный адрес, который добрался до порта
посетителя в локальной сети, не пересылается на сервер как доверенный источник.

## Что вы получаете

При конфигурациях выше обращение к `127.0.0.1:18080` на машине посетителя приводит к
`127.0.0.1:3000` на агенте офиса, а UDP `127.0.0.1:15353` соответствует `127.0.0.1:5353` на офисе.

Соединения и необработанный трафик учитываются и за посетителя, и за поставщика, а также за их
ресурсы пользователя и туннеля; когда один пользователь владеет обеими сторонами, использование
обеих сторон суммируется. Заголовки длины UDP и сообщения аутентификации общего доступа не
учитываются как рабочий трафик.

## Динамические цели

Когда общий доступ на сервере задаёт `dynamic = true`, посетитель может назвать цель:

```toml
[[visitor]]
name = "office-proxy"
share = "office-proxy"
secret = "replace-this-shared-secret"
bind = "127.0.0.1:11080"
mode = "socks5"
target = "internal.example:443"
```

- Поставщик должен быть туннелем SOCKS5, прямым прокси HTTP или смешанным прокси; цели UDP требуют
  SOCKS5 или смешанного прокси.
- Фактический разрешённый IP-адрес поставщика и политика целей по-прежнему проверяются.
- Динамический общий доступ требует, чтобы у входа прокси **не было отдельных учётных записей
  прокси**; при настроенных учётных записях запрос отклоняется, чтобы общий секрет не мог обойти
  собственную аутентификацию прокси.
- Без поля `target` посетитель подключается ко всей точке входа сервиса; файловые учётные записи и
  учётные записи прокси по-прежнему аутентифицируются обычным порядком.
- TCP-посетитель может пропустить сеанс SOCKS CONNECT или HTTP-прокси; UDP-адрес сервера,
  возвращённый SOCKS UDP ASSOCIATE, не отображается автоматически на локальный адрес на посетителе.

Когда вам нужен полный доступ SOCKS5, задайте посетителю `mode = "socks5"` и сошлитесь на
динамический общий доступ, без поля `target`: SOCKS CONNECT и UDP ASSOCIATE разрешаются на стороне
посетителя, и каждый адрес назначения проходит через аутентификацию общего доступа и политику целей
поставщика. Секция `[visitor.auth.users]` настраивает локальные учётные записи SOCKS, а при наличии
учётных записей посетитель не понижает уровень до анонимной аутентификации. Поле `max_connections`
учитывает управляющие соединения SOCKS и ассоциации целей UDP вместе, поэтому при использовании UDP
задавайте не менее 2.

## Управление и работа

- Страница управления «Общий доступ» создаёт, изменяет и удаляет общие доступы; секреты по умолчанию
  скрыты, а пустое поле при изменении сохраняет текущее значение.
- Операторы могут управлять только общими доступами на стороне поставщика для принадлежащих им
  пользователей; учётные записи только для чтения не могут вносить изменения.
- API — это `/api/shares` и `/api/shares/NAME`; записи сохраняют версию конфигурации и ключ
  идемпотентности запроса.
- После обрыва моста локальный слушатель сохраняется, существующие сеансы завершаются, а новые
  запросы возобновляются после переподключения.
- Изменения общего доступа вступают в силу при обычной перезагрузке службы, а существующие
  соединения разрываются.
- Этот трафик идёт через релей сервера; о прямом соединении см. [Прямое соединение P2P и откат на
  релей](p2p.md).

## Контрольный список проверки

1. Команда `--check` на сервере и `--check` на обоих агентах завершаются успешно.
2. Адрес `127.0.0.1:18080` на посетителе возвращает содержимое `127.0.0.1:3000` на поставщике.
3. Соединение посетителя с неверным `secret` отклоняется.
4. Узлы вне списка `allow_clients` отклоняются.
5. У сервера не появилось нового публичного слушателя (сравните с выводом `ss -ltnp`).
