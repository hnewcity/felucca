# フォワードプロキシ

Felucca は NAT の背後から SOCKS5 または HTTP のプロキシ入口を公開できます。このページでは 3 つの
モード、アカウント認証、対象 ACL、UDP の挙動を取り上げます。

## 3 つのモード

```toml
[[tunnel]]
mode = "socks5"
port = 9080
bind = "127.0.0.1"
acl_mode = "allow"
acl_rules = "127.0.0.0/8, ::1/128"

[[tunnel]]
mode = "httpproxy"
port = 9081
bind = "127.0.0.1"

[[tunnel]]
mode = "mixedproxy"
port = 9082
bind = "127.0.0.1"
```

| `mode` | 対応 |
| --- | --- |
| `socks5` | CONNECT と UDP ASSOCIATE。IPv4/IPv6。名前解決はエージェント側で行います。BIND は "unsupported command" を返します |
| `httpproxy` | 絶対 URL のリクエストと CONNECT |
| `mixedproxy` | リクエストの先頭で SOCKS5 と HTTP を判別します |

フォワードプロキシのサンプルは `127.0.0.1` にのみバインドしています。リモートからアクセスする必要が
ある場合は、送信元の許可リストも**あわせて**設定してください。そうしないと、そのポートに到達できる
誰もがあなたのエグレスを使えてしまいます。

## アカウント認証

認証を有効にするには、対象のトンネルの下にアカウントテーブルを追加します。

```toml
[tunnel.options.auth.users]
alice = "replace-with-a-password"
bob = "another-password"
```

| 入口 | 認証 | 失敗時の応答 |
| --- | --- | --- |
| SOCKS5 | ユーザー名とパスワード方式。匿名への**ダウングレードはありません** | 認証失敗 |
| HTTP フォワードプロキシ / CONNECT | `Proxy-Authorization: Basic` | 407 |
| HTTP リバースプロキシのサイト | `Authorization: Basic` | 401 |

アカウントテーブルがない場合、匿名アクセスが許可されます。検証済みのプロキシとサイトの資格情報は、
バックエンドへリクエストを送る前に取り除かれます。設定と登録メッセージにはアカウントのパスワードが
含まれるため、ブリッジは既定の TLS、WSS または QUIC を使うべきです。`tcp` と `ws` は明確に選んだ
平文の通信方式です。

ファイルトンネルは `tunnel.file.auth` を使い、これは `tunnel.options.auth` と同時に使うことは
できません。

## 対象ポリシー

固定のバックエンドを持つトンネルは `target_policy` で実際の接続先を制限します。フォワードプロキシでは
これが特に必要です。

```toml
[tunnel.target_policy]
allow = ["domain:api.example.com", "suffix:example.net", 'regex:^db[0-9]+\.internal$']
deny = ["127.0.0.0/8", "::1", "169.254.0.0/16"]
ports = [80, 443]
```

`allow` が空の場合、どの対象を許可するかの制限はありません。`deny` は常に優先され、`ports` が空の
場合は 0 以外の任意のポートを許可します。指定できるルールは IP/CIDR、完全なドメイン名を指定する
`domain:`、サフィックスを指定する `suffix:`（ルートドメインと任意の深さのサブドメインを含む）、
正規表現を指定する `regex:`、そしてすべての対象に一致する `*` です。名前の大文字と小文字は区別
されず、末尾のドットは正規化されます。

まず DNS が解決され、次に**元の名前と実際の IP** が一つずつ検査されます。接続が使うのは検査を通過した
アドレスだけであり、2 回目の名前解決は行われないため、許可されたドメインを使って拒否された IP に
抜け道を作ることはできません。GeoIP と GeoSite にも対応しています。
[アクセス制御、クォータ、ストリーム符号化](security.md) を参照してください。

## SOCKS5 の UDP ASSOCIATE

- 受け付けるのは制御接続の相手の IP だけです。リクエストでポートが指定された場合はそのポートに固定
  され、指定がない場合は最初の有効な UDP パケットの送信元ポートに紐づけられます。
- 制御用の TCP 接続を閉じると、対象の関連づけはすべて解除されます。
- 1 セッションあたりの対象は最大 64 件で、それぞれ 8 パケットまでキューイングし、アイドル状態の
  エントリは 60 秒後に回収されます。
- FRAG が 0 以外のパケットは破棄されます。SOCKS のフラグメント再構成には対応していません。

## レートとクォータ

- `tunnel.options.limits.rate_limit` は、エージェントのすべてのトンネルと双方向で共有される 1 秒
  あたりのバイト数の上限で、最初の 1 秒分のトラフィックに相当するバーストを許可します。
- `quota.flow_limit` は双方向をカウントし、`quota.expires_at` は Unix 秒を使います。
- クォータは定期的に確認され、転送中の接続を中断させるため、同時に進行中のトラフィックはクォータを
  超えることがあります。このカウントを厳密な課金に使うことは想定していません。
