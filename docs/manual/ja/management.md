# 管理 UI と集中構成

`felucca-server` は端末、サービス、プライベートアクセス、設定の管理画面を提供します。日常の変更はオンラインで同期され、未変更のサービスは動作を続けます。全体のリスナー設定などの変更時は転送を再読み込みしますが、管理 API は利用できます。

## 設定ファイルを編集せずに接続する

1. **端末 → 端末を接続**で名前とサーバーアドレスを指定し、OS とプロセッサーを選びます。クライアントパッケージを展開して `Connect.command`（macOS）または `Connect.cmd`（Windows）を開きます。Linux では展開先で `sh connect.sh` を実行します。プログラムと接続情報が含まれ、追加ダウンロードや設定編集は不要です。
2. **サービス → サービスを追加**で端末、種類、端末上のアプリのアドレスを選びます。公開アクセスはサーバーのポートやドメインを使い、プライベートアクセスは許可した端末だけで使います。識別子と認証情報は自動生成されます。
3. 接続先端末にも個別のクライアントパッケージを用意し、表示されたローカルアドレスを使用します。ログイン後に自動起動するには、接続ウィンドウを閉じてから `Install.command`、`Install.cmd`、または `sh install.sh` を実行します。クライアントは個人フォルダーに保存されます。

主な画面は概要、端末、サービス、プライベートアクセス、監視、設定です。アカウント、割当、診断、サーバー設定、外部連携は設定に集約されています。通常操作と詳細設定に JSON エディターは必要ありません。

設定で直接接続を有効にすると、接続先端末は直接接続を優先し、失敗時にはサーバー中継を使います。無効なら中継を使います。これはサービス単位の接続であり、システム全体の VPN ではありません。ファイル共有には端末上に存在するフォルダーの許可が必要です。接続ファイルには認証情報が含まれます。受信端末の元のファイルを保管し、紛失した場合は新しい接続を作成してください。端末・サービス・権限の変更では全転送を再起動しません。変更・無効化したサービスの接続のみ終了します。未変更のサービスと名前の変更は接続を維持します。旧版 agent は対象端末のみ再接続します。ブリッジ、HTTP、P2P リスナーなど全体設定は再読み込みが必要です。

サーバーにあるクライアントのみ選択できます。Apple の公証を受けていない macOS 版は明示され、通常のダウンロード後に起動がブロックされる場合があります。システム保護を無効にせず、管理者に正式リリース版を依頼してください。

## 有効化

```sh
target/release/felucca-server --hash-password      # read one password line from stdin; >=12 bytes
target/release/felucca-server --generate-token     # Bearer token and its stored hash
```

```toml
[admin]
bind = "127.0.0.1:8088"
state_path = "state/runtime-config.json"
profiling = true
# required for non-loopback binds: the origin the browser uses; use https://
# unless you accept plaintext management traffic (then http://host:port)
# origin = "https://admin.example.com"

[admin.account.root]
role = "admin"
password_hash = "pbkdf2-sha256$600000$..."
```

設定ファイルは TOML でも JSON でも構いません。この例では管理アドレスを
`http://127.0.0.1:8088`、アカウントを `root` としています。例のパスワードはローカルデモ専用
です。実際のデプロイでは自分のハッシュに置き換えてください。

## アカウントとロール

| `role` | 権限 |
| --- | --- |
| `admin` | すべてのリソースとアカウントを管理します。`user` フィールドは設定しません |
| `operator` | 割り当てられた `user` のノードと集中管理トンネルを管理します |
| `viewer` | 割り当てられた `user` のリソースへの読み取り専用アクセス |

operator と viewer のアカウントは、存在するユーザーを参照する必要があります。サーバー上の
ローカルサービスはローカルのディレクトリに到達できるため、変更できるのは管理者だけです。
ユーザーのクォータ、管理者アカウント、設定全体も管理者専用です。有効な管理者アカウントを
少なくとも 1 つは残してください。`disabled = true` でアカウントを無効化できます。

パスワードは PBKDF2-SHA256 を、ランダムなソルトと固定の 600000 回の反復で使います。セッションは
メモリ上に保持されます。Cookie は HttpOnly と SameSite=Strict が設定され、HTTPS を設定した場合は
Secure も併せて設定されます。ブラウザからの書き込みには同一オリジンの Origin と CSRF トークンが
必要です。パスワードの変更、アカウントの無効化、アカウントの削除を行うと古いセッションは無効に
なり、プロセスの再起動でも Cookie のセッションは無効になります。

自動化のためには Bearer トークンを使ってください。`token_hash` は `--generate-token` の出力に
表示されます。その値をアカウントの `token_hash` にコピーし、各リクエストで生のトークンを
送ります。Bearer のリクエストに Cookie の CSRF トークンは不要ですが、同じアカウントの権限確認は
引き続き適用されます。**生のトークンをサーバーの設定ファイルに書いてはいけません。**

## 書き込みトランザクション

すべての書き込みには 2 つのヘッダーが必要です。

```text
If-Match: "current configuration revision"
Idempotency-Key: unique identifier for this operation
```

- 古いリビジョンでは 409 を返します。
- 同じ ID で同じリクエストの場合は以前の結果を返し、データプレーンを再度再起動することは
  **ありません**。同じ ID で違うリクエストの場合は 400 を返します。
- 成功した最新 256 件の操作が設定と一緒に保存されるため、DELETE のような操作の再試行は再起動後も
  認識されます。
- `durable = false` は、ディレクトリへの同期がまだ確認されていないことを意味します。
- 端末・サービス・権限の変更では全転送を再起動しません。変更・無効化したサービスの接続のみ終了します。未変更のサービスと名前の変更は接続を維持します。旧版 agent は対象端末のみ再接続します。ブリッジ、HTTP、P2P リスナーなど全体設定は再読み込みが必要です。

管理用のバインドアドレス、証明書ファイルのパス、公開オリジン、状態のパスを変更するにはプロセスの
再起動が必要です。サーバーの実行中に変更することはできません。

## UI のページ

| ページ | 内容 |
| --- | --- |
| 概要 | 現在のアカウントで確認できる端末、サービス、接続の状態。 |
| デバイス | 接続したパソコンやサーバーを選び、サービスを管理します。 |
| サービス | デバイスとアクセスするアプリを選択します。Felucca が選んだ入口へ接続します。 |
| プライベートアクセス | 非公開サービスを選び、別のデバイス用の接続ファイルを作成します。サービスの公開ポートは不要です。 |
| 監視 | ホストのメトリクス、接続数、累積通信量を確認します。 |
| 設定 | サーバー接続、アクセス権限、外部連携を管理します。日常の操作はメインナビから行えます。 |

## API

API は JSON を使い、リクエストボディは最大 2 MiB まで受け付け、ブラウザからのクロスオリジン
リクエストは拒否します。読み取りでは通常 `{revision, config}` を返し、設定の読み取りでは既定で
シークレットが伏せられます。編集時に、既存の `<redacted>` プレースホルダはそのフィールドの現在値を
保持します。新しいリソースの資格情報にこのプレースホルダを使うことはできません。

| パス | メソッドと用途 |
| --- | --- |
| `/api/login` | `{account, password}` を POST します。Origin が必要です |
| `/api/session` | 現在の識別情報と CSRF トークンを GET します |
| `/api/logout` | POST で Cookie のセッションを無効にします |
| `/api/overview` | オンラインのノード、接続、トラフィック、登録済みのトンネルを GET します |
| `/api/users`、`/api/users/<id>` | 一覧または 1 件を GET します。1 件には PUT と DELETE が使えます |
| `/api/clients`、`/api/clients/<id>` | 一覧または 1 件を GET します。1 件には PUT と DELETE が使えます |
| `/api/managed/<client>` | 集中構成全体を GET、PUT します。DELETE するとローカルの設定に戻します |
| `/api/managed/<client>/tunnels/<id>` | 1 つのトンネルを GET、PUT、DELETE します |
| `/api/locals`、`/api/locals/<id>` | 一覧または 1 件を GET します。1 件には PUT と DELETE が使えます |
| `/api/locals/<group>/tunnels/<id>` | サーバー上のローカルトンネルを PUT、DELETE します |
| `/api/shares`、`/api/shares/<name>` | プライベート共有を GET、PUT、DELETE します |
| `/api/accounts`、`/api/accounts/<id>` | 一覧を GET します。1 件には PUT と DELETE が使えます |
| `/api/config` | シークレットを伏せた設定全体を GET します。PUT で設定全体をインポートします |
| `/api/config?secrets=1` | 管理者専用の明示的なエクスポートで、資格情報も含みます |
| `/api/validate` | リスナーを起動せずに設定全体を検証する POST |
| `/api/batch` | アトミックな変更のバッチを POST します。操作は最大 128 件です |
| `/api/events` | 設定のリビジョン変更を SSE で受ける GET。ハートビートは 10 秒で、セッションを再確認します |
| `/metrics`、`/api/metrics` | Prometheus のメトリクスを GET します。アカウントの権限で絞り込みます |
| `/api/profile` | 時間制限付きの CPU フレームグラフをダウンロードする POST |

バッチは 1 つのリビジョンと 1 つの操作 ID を使います。すべての操作は何かが適用される前に検証され、
いずれかの操作が範囲外であるか設定が無効な場合は、先行する操作も含めて何もコミットされません。

```json
{
  "operations": [
    {
      "method": "PUT",
      "path": "/api/managed/office/tunnels/1",
      "value": {
        "id": 1,
        "enabled": false,
        "mode": "tcp",
        "port": 18080,
        "backend": [{"addr": "127.0.0.1:3000"}]
      }
    }
  ]
}
```

アカウントを `PUT` するときに `password` を送ると、サーバーがハッシュを生成します。省略した場合は
既存の `password_hash` が保持されます。

## 集中構成

サーバーは、エージェントが実行すべき設定を `[managed.<client-id>]` の下に保存します。

```toml
[[managed.office.tunnel]]
id = 1
mode = "tcp"
port = 18080
bind = "127.0.0.1"
backend = [{ addr = "127.0.0.1:3000" }]
```

エージェントは `[remote] enabled = true` を明示的に有効にする必要があり、主接続は認証済みの
TLS/WSS/QUIC を使う必要があります。サーバーは実際のブリッジが暗号化されていることも確認するため、
平文の接続では設定を要求できません。プッシュはダイジェスト付きの正規化された JSON を使い、設定中の
資格情報が制御メッセージのデバッグログに現れることはありません。

管理プレーンで変更できるのはトンネルの内容だけです。新しいエージェントの識別情報、出口プロキシ、
サーバー上のローカルの認可境界をプッシュすることはできません。ファイルサービスでは、名前付きの
ディレクトリ機能を事前に設定しておく必要があります。
[ファイルサービスと WebDAV](file-services.md) を参照してください。

例外として、エージェントが `remote.console_scope = true` を設定している場合は、`[managed.<client-id>]` の `target_policy` が宛先範囲を置き換えます。

| 操作 | 効果 |
| --- | --- |
| `tunnel.enabled = false` | 設定と安定した ID は保持しますが、リスナーを登録せず、バックエンドのプローブも開始しません |
| `managed` のエントリを空のままにする | そのノードの集中管理トンネルをすべて停止します |
| `managed` のエントリ全体を削除する | エージェントのローカルのトンネル設定を起動時の状態に戻します |

管理画面では「公開済み」「ノードによる適用待ち」「無効」が区別されます。

## 確認チェックリスト

1. `felucca-server --config server.json --check` が成功します。
2. ブラウザで管理アドレスを開いてサインインし、JS のエラーが出ないことを確認します。
3. TCP トンネルを作成し、バックエンドが実際に内容を返すことを確認します。
4. `GET /api/config` に平文のシークレットが含まれていないことを確認します。
5. サーバーを再起動したあとも設定とトンネルが残っており、同じ `Idempotency-Key` で再試行しても
   変更が 2 重に適用されないことを確認します。

コンソールはバックエンドの重みと TLS、ヘルスチェック、HTTP 経路、サービス認証、ACL と割当、ファイルサービス、ローカルトンネル群とポート対応を構造化フォームで設定できます。アカウント画面では管理トークンを生成、更新、失効でき、新しいトークンは保存後にダウンロードされます。

検証では再起動が必要な設定を表示します。再起動用の出力には認証情報を含む起動設定、実行時スナップショットとオフライン置換の手順が含まれます。まずプロセスを停止し、既存ファイルをバックアップしてください。実行時スナップショットは起動ファイルより優先され、`--runtime-config` の指定も対象です。流量とプラットフォームの履歴を保持し、稼働中のスナップショットを上書きしないでください。

診断にはトンネル別の流量、既存のバックエンド探査結果、活動中の P2P セッションと最近の中継イベントが表示されます。管理者は使用中の証明書の確認、失敗した ACME 要求の再試行、PEM 証明書と鍵の設定下書きへの追加、および認証情報を秘匿したサイズ制限付きログ末尾の確認ができます。任意の診断ストリームを実装しない旧 agent は利用不可と表示されますが、転送は継続します。診断は追加の探査を開始しません。Agent と訪問者の設定生成はローカルのディレクトリと宛先の許可を保持します。生成ファイルを agent 上で確認し、起動前にそこで `--check` を実行してください。サービスと更新のコマンドは確認用で、コンソールから実行されません。
