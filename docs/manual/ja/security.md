# アクセス制御、クォータ、ストリーム符号化

このページではセキュリティに関わる設定をまとめます。送信元 ACL、対象 ACL、GeoIP/GeoSite、
階層的なクォータとレート制限、トラフィックのスナップショット、そしてトンネルごとに選べる
圧縮と暗号化です。

## 送信元 ACL

```toml
[client.agent-1]
acl_mode = "allow"                 # off | allow | deny
acl_rules = "203.0.113.0/24, 2001:db8::/32"
```

ルールはカンマまたは改行で区切った IP/CIDR のエントリです。サーバーのトップレベルの
`acl_mode`/`acl_rules`、`[user.<name>]`、`[client.<id>]`、トンネルのルールは**交わり**ます。
クライアントは自分の設定の `user = "<name>"` によってユーザーに関連づけられ、エージェントはその
関連づけを変更できません。

これらのルールは公開入口に到達するクライアントに適用され、エージェントのブリッジアドレスを拒否する
ためには**使われません**。ブリッジの身元は vkey で検証されます。ルールが対象とするのはプロキシに
到達するクライアントの送信元 IP であり、対象のアドレスではありません。

送信元 ACL は GeoIP に対応しています。`acl_rules` は `[[tunnel]]`、`[local.<name>]`、
`[[visitor]]` にも記述できます。

## 対象ポリシー

エージェント側で強制され、固定のバックエンド、ヘルスプローブ、フォワードプロキシの対象に
適用されます。

```toml
[tunnel.target_policy]
allow = ["domain:api.example.com", "suffix:example.net", 'regex:^db[0-9]+\.internal$']
deny = ["127.0.0.0/8", "::1", "169.254.0.0/16"]
ports = [80, 443]
```

| 項目 | 説明 |
| --- | --- |
| `allow` が空 | 許可する対象に対する制限はありません |
| `deny` | 常に優先されます |
| `ports` が空 | 0 以外の任意のポートを許可します |
| 構文 | IP/CIDR、`domain:`、`suffix:`、`regex:`、`*` |
| 地理情報 | `geoip:CN`、`geosite:category-ads-all`、`geosite:custom:LOCAL@fast@!ads` |

`@attribute` はその属性が存在することを要求し、`@!attribute` は存在しないことを要求します。
複数の条件は交わります。`geoip:private` は組み込みの IPv4/IPv6 のプライベート、ループバック、
リンクローカル、CGNAT の範囲を対象とし、データファイルは不要です。名前と解決された IP は
一緒に確認されます。名前の大文字と小文字は区別されず、末尾のドットは正規化されます。

ファイルの欠如、グループの欠如、不正な正規表現、壊れた protobuf は**エラー**であり、すべてを
許可する空のルールに格下げされることはありません。データは起動時に読み込まれるため、データ
ファイルを更新したら該当するプロセスを再起動してください。各端は自分でローカルに宣言した
データファイルを使い、遠隔側が参照できるのはグループとエイリアスだけです。

## 地理情報データ

```toml
[geo]
geoip = "data/geoip.dat"
geosite = "data/geosite.dat"

[geo.extra]
mycorp = "data/mycorp.dat"
```

これらは V2Ray の protobuf 形式の `.dat` ファイルを指し、パスはプロセスの作業ディレクトリからの
相対パスです。IP のプレフィックスはコンパイル済みの範囲検索を使い、ドメインは完全一致、サフィックス、
キーワード、正規表現の一致に対応します。

## 階層的なクォータ

`[user.<name>.limits]`、`[tunnel.options.limits]`、
`[http.host_limit."<domain pattern>"]` は同じフィールドを受け付けます。

```toml
max_connections = 20
rate_limit = 1048576
quota = { flow_limit = 1073741824, expires_at = 1893456000 }
```

トラフィックとレートの単位はバイトで、`expires_at` は Unix 秒です。フィールドを省略した場合は
制限なしを意味します。レートの 0 は制限なしですが、接続数の 0 は新しい接続を明示的に禁止します。
1 人のユーザーの複数のクライアント、1 つのトンネルの複数の接続、1 つのドメインの複数のパスは、
それぞれ独自のカウンタと上限を共有します。

複数のレートの層は同時に請求され、待ち時間は**最も厳しい層**を採用します。接続スロットの要求が
失敗した場合は、前の層から与えられたスロットは返されます。HTTP のドメイン制限は元の Host/SNI で
選ばれ、完全一致するドメインがワイルドカードより優先され、バックエンド側の Host の書き換えの
影響を受けません。HTTP の接続のカウントは実際のバックエンド接続を対象とし、複数の HTTP/2
リクエストは 1 本の接続を再利用できます。

TCP、HTTP、SNI、UDP はすべての層のカウンタを更新します。TCP は 16 KiB のブロック単位で確認と
レート制限が行われ、UDP はデータグラム単位で扱われます。並行して転送中のトラフィックによって
合計がクォータをわずかに超えることがあるため、これは**バイト単位の厳密な打ち切りではありません**。
HTTP はバックエンドのプロトコルのバイトをカウントし、ヘッダーとプロトコルのオーバーヘッドを
含みます。UDP はペイロードだけをカウントします。クォータは転送中の接続を中断させ、カウントを
厳密な課金に使うことは想定していません。

## トラフィックのスナップショット

```toml
[state]
path = "data/traffic.json"
save_interval = "5s"
```

有効にすると、スナップショットはその間隔でアトミックに置き換えられ、通常の終了時と接続の終了後に
最終的なカウントが保存されます。スナップショットにはオフラインのリソースも含まれるため、サーバーを
再起動した後もそれらはクォータに対してカウントされ続けます。クラッシュすると最後の保存間隔分の
データを失うことがあります。1 つのスナップショットを書き込めるサーバーは 1 つだけです。壊れた
スナップショット、または未知のバージョンのスナップショットは起動を拒否し、元のファイルは
保持されます。

これはトラフィックのスナップショットです。管理 UI の実行時の設定は `admin.state_path` /
`--runtime-config` に別途保存され、両者は同じパスを使ってはいけません。スナップショットを有効に
したら、トンネルの `id` は固定してください。

## ストリームごとの符号化

```toml
[tunnel.options.payload]
compress = true
encrypt = true
```

| オプション | 実装 | 動作 |
| --- | --- | --- |
| `compress` | Snappy | 最大 16 KiB の生データのブロック単位で動作し、小さくなった場合だけ圧縮ブロックを使います。伸長前に宣言されたサイズを確認します |
| `encrypt` | ChaCha20-Poly1305 | ストリームごとに新しいノンスを交換し、エージェントの vkey が両側の身元とルーティング要求全体を検証します。HKDF によって 2 つの独立した方向鍵を導出します |

圧縮を有効にすると、データは**暗号化される前に圧縮されます**。長さヘッダー、シーケンス番号、
終端レコードは完全性の確認の対象となり、改ざん、リプレイ、終端レコードの欠如はデータストリームを
閉じます。両端で設定が一致しない場合はネゴシエーションが拒否され、平文への自動フォールバックは
ありません。各方向は上限付きのレコードを 1 つだけバッファリングします。

この符号化の層は mux/QUIC のストリームの内部にあり、独自の多重化の層は追加しません。PROXY
ヘッダー、HTTP/WebDAV の内容、UDP のデータグラムはすべて同じ符号化を通ります。トラフィックの
クォータとレート制限は**生の転送バイト数**で計算されます。

セキュリティの境界は以下のとおりです。

- 独立した暗号化が保護するのはルーティングのデータ部分です。設定の登録とブリッジの制御メッセージは
  引き続き選んだブリッジの通信方式によって保護されるため、TLS、WSS または QUIC が既定のデプロイの
  選択であり続けます。
- この PSK の層は**それ自体では前方秘匿性を提供しません**。
- 圧縮は観測可能なレコードサイズを変えます。圧縮の特徴を隠す必要がある場合は
  `compress = false` にしてください。

## シークレットの扱い

- 生のシークレットがログに出力されることはありません。Debug と Display の出力は伏せられます。
- 永続化ではシークレットを保持し、伏せるのは表示するときだけです。資格情報のフィールドを追加する
  ときは、同時に伏せる処理も確認してください。
- 設定のスナップショットには実際のシークレットが含まれ、Unix では新しいファイルは 0600、新しい
  ディレクトリは 0700 になります。
- 生の管理用 Bearer トークンをサーバーの設定ファイルに書いてはいけません。`token_hash` だけを
  書いてください。
