# 접근 제어, 할당량과 스트림 부호화

이 페이지에서는 보안 관련 설정을 모아 설명합니다. 출발지 ACL, 대상 ACL, GeoIP/GeoSite,
계층형 할당량과 속도 제한, 트래픽 스냅샷, 그리고 터널별로 선택하는 압축과 암호화입니다.

## 출발지 ACL

```toml
[client.agent-1]
acl_mode = "allow"                 # off | allow | deny
acl_rules = "203.0.113.0/24, 2001:db8::/32"
```

규칙은 쉼표나 줄바꿈으로 구분한 IP/CIDR 항목입니다. 서버의 최상위
`acl_mode`/`acl_rules`, `[user.<name>]`, `[client.<id>]`, 터널 규칙은 **교집합**으로
적용됩니다. 클라이언트는 자신의 설정에서 `user = "<name>"`로 사용자와 연결하며,
에이전트는 그 연결을 바꿀 수 없습니다.

이 규칙은 공개 진입점에 도달하는 클라이언트에 적용되며, **에이전트의 브리지 주소를
거부하는 데는 쓰이지 않습니다**. 브리지 신원은 vkey로 검증합니다. 규칙은 대상 주소가
아닌, 프록시에 도달하는 클라이언트의 출발지 IP에 동작합니다.

출발지 ACL은 GeoIP를 지원합니다. `acl_rules`은 `[[tunnel]]`, `[local.<name>]`,
`[[visitor]]`에도 쓸 수 있습니다.

## 대상 정책

에이전트 쪽에서 집행되며, 고정 백엔드, 헬스 프로브, 포워드 프록시 대상에 적용됩니다.

```toml
[tunnel.target_policy]
allow = ["domain:api.example.com", "suffix:example.net", 'regex:^db[0-9]+\.internal$']
deny = ["127.0.0.0/8", "::1", "169.254.0.0/16"]
ports = [80, 443]
```

| 항목 | 설명 |
| --- | --- |
| `allow` 비어 있음 | 허용하는 대상을 제한하지 않습니다 |
| `deny` | 항상 우선합니다 |
| `ports` 비어 있음 | 0이 아닌 모든 포트를 허용합니다 |
| 문법 | IP/CIDR, `domain:`, `suffix:`, `regex:`, `*` |
| Geo | `geoip:CN`, `geosite:category-ads-all`, `geosite:custom:LOCAL@fast@!ads` |

`@attribute`는 해당 속성이 있어야 함을, `@!attribute`는 없어야 함을 뜻하며, 여러 조건은
교집합으로 적용됩니다. `geoip:private`는 내장된 IPv4/IPv6 사설, 루프백, 링크 로컬,
CGNAT 범위를 포함하며 데이터 파일이 필요하지 않습니다. 이름과 조회된 IP를 함께
검사하며, 이름은 대소문자를 구분하지 않고 끝의 점은 정규화합니다.

파일이 없거나, 그룹이 없거나, 정규 표현식이 잘못되었거나, protobuf가 깨진 경우 **오류**로
처리하며, 모두 허용하는 빈 규칙으로 약화되지 않습니다. 데이터는 시작할 때 로드하므로,
데이터 파일을 업데이트한 뒤에는 관련 프로세스를 재시작하세요. 각 쪽은 자신이 로컬에
선언한 데이터 파일을 사용하며, 원격 쪽은 그룹과 별칭만 참조할 수 있습니다.

## Geo 데이터

```toml
[geo]
geoip = "data/geoip.dat"
geosite = "data/geosite.dat"

[geo.extra]
mycorp = "data/mycorp.dat"
```

V2Ray protobuf `.dat` 파일을 가리키며, 경로는 프로세스 작업 디렉터리를 기준으로 합니다.
IP 프리픽스는 컴파일된 범위 조회를 사용하고, 도메인은 정확 일치, 접미사, 키워드, 정규
표현식 매칭을 지원합니다.

## 계층형 할당량

`[user.<name>.limits]`, `[tunnel.options.limits]`,
`[http.host_limit."<domain pattern>"]`는 같은 필드를 받습니다.

```toml
max_connections = 20
rate_limit = 1048576
quota = { flow_limit = 1073741824, expires_at = 1893456000 }
```

트래픽과 속도 단위는 바이트이며, `expires_at`는 Unix 초입니다. 필드를 빼면 제한이
없으며, 속도 0은 제한 없음을 뜻하지만 연결 0은 새 연결을 명시적으로 차단합니다. 한
사용자의 여러 클라이언트, 한 터널의 여러 연결, 한 도메인의 여러 경로는 각자 카운터와
제한을 공유합니다.

여러 속도 계층은 동시에 부과되며, 대기 시간은 **가장 엄격한 계층**을 따르고, 연결 슬롯
요청이 실패하면 앞선 계층이 부여한 슬롯을 돌려줍니다. HTTP 도메인 제한은 원래
Host/SNI로 선택하며, 정확한 도메인이 와일드카드보다 우선하고 백엔드 Host 재작성의
영향을 받지 않습니다. HTTP 연결 카운트는 실제 백엔드 연결을 대상으로 하며, 여러 HTTP/2
요청이 하나의 연결을 재사용할 수 있습니다.

TCP, HTTP, SNI, UDP는 모두 모든 계층의 카운터를 갱신합니다. TCP는 16 KiB 블록 단위로
검사하고 속도를 제한하며, UDP는 데이터그램 단위로 처리합니다. 동시 전송 중인
트래픽으로 총량이 할당량을 약간 넘을 수 있으므로, 이는 바이트 단위의 정확한 차단이
**아닙니다**. HTTP는 백엔드 프로토콜 바이트를 세며 헤더와 프로토콜 오버헤드를
포함하고, UDP는 페이로드만 셉니다. 할당량에 도달하면 전송 중인 연결을 중단시키며,
이 카운트는 엄격한 과금 용도가 아닙니다.

## 트래픽 스냅샷

```toml
[state]
path = "data/traffic.json"
save_interval = "5s"
```

활성화하면 스냅샷이 해당 간격마다 원자적으로 교체되고, 정상 종료 시와 연결이 끝난 뒤에
최종 카운트가 저장됩니다. 스냅샷은 오프라인 리소스도 포함하므로, 서버를 재시작한 뒤에도
할당량에 계속 반영됩니다. 충돌이 나면 마지막 저장 간간의 데이터를 잃을 수 있습니다.
스냅샷 하나는 서버 하나만 쓸 수 있습니다. 깨진 스냅샷이나 알 수 없는 버전의 스냅샷은
시작을 거부하며, 원본 파일은 유지합니다.

이것은 트래픽 스냅샷입니다. 관리 UI의 런타임 설정은 `admin.state_path` /
`--runtime-config`에 별도로 저장되며, 둘은 같은 경로를 쓰면 안 됩니다. 스냅샷을
활성화하면 터널의 `id`를 고정하세요.

## 스트림별 부호화

```toml
[tunnel.options.payload]
compress = true
encrypt = true
```

| 옵션 | 구현 | 동작 |
| --- | --- | --- |
| `compress` | Snappy | 원시 데이터 최대 16 KiB 블록 단위로 동작하며, 더 작을 때만 압축 블록을 사용합니다. 선언된 크기는 압축 해제 전에 검사합니다 |
| `encrypt` | ChaCha20-Poly1305 | 스트림마다 새로운 nonce를 교환하고, 에이전트의 vkey가 양쪽 신원과 전체 라우팅 요청을 검증합니다. HKDF로 두 개의 독립적인 방향별 키를 도출합니다 |

압축을 활성화하면 데이터를 **암호화하기 전에 압축합니다**. 길이 헤더, 시퀀스 번호,
종료 레코드는 무결성 검사의 범위에 포함되며, 변조나 재생, 종료 레코드 누락은 데이터
스트림을 닫습니다. 양쪽 설정이 맞지 않으면 협상을 거부하며, 평문으로의 자동 대체는
없습니다. 각 방향은 범위가 제한된 레코드를 하나만 버퍼링합니다.

이 부호화 계층은 mux/QUIC 스트림 내부에 있으며, 자체 멀티플렉싱 계층을 추가하지
않습니다. PROXY 헤더, HTTP/WebDAV 콘텐츠, UDP 데이터그램은 모두 같은 부호화를
거칩니다. 트래픽 할당량과 속도 제한은 여전히 **원시 전달 바이트**로 계산합니다.

보안 경계는 다음과 같습니다.

- 독립 암호화는 라우팅의 데이터 부분을 보호합니다. 설정 등록과 브리지 제어 메시지는
  여전히 선택한 브리지 전송이 보호하므로, TLS, WSS, QUIC이 기본 배포 선택으로 남습니다.
- 이 PSK 계층은 그 자체만으로 **순방향 비밀성을 제공하지 않습니다**.
- 압축은 관찰 가능한 레코드 크기를 바꿉니다. 압축 특징을 숨겨야 한다면
  `compress = false`를 유지하세요.

## 시크릿 처리

- 원시 시크릿은 로그에 절대 남지 않습니다. Debug와 Display 출력은 마스킹됩니다.
- 영속화는 시크릿을 유지해야 하며, 마스킹은 출력할 때만 일어납니다. 자격 증명 필드를
  추가할 때는 마스킹 경로도 함께 확인하세요.
- 설정 스냅샷은 실제 시크릿을 담고 있으며, Unix에서는 새 파일이 0600, 새 디렉터리가
  0700입니다.
- 원시 관리 Bearer 토큰을 서버 설정에 쓰지 마세요. `token_hash`만 기록하세요.
