# 서버 로컬 대상과 중첩 라우트

`[local.<name>]`를 쓰면 에이전트도 브리지 자격 증명도 없이 서버가 직접 서비스를 제공할
수 있습니다. 로컬 터널의 백엔드는 별칭으로 다른 등록된 터널(에이전트의 터널 포함)에
들어갈 수도 있으며, 이를 조합하면 중첩 라우트가 됩니다.

## 로컬 서비스 묶음

```toml
[user.office]
[user.office.limits]
max_connections = 100

[local.office]
user = "office"
dial_timeout = "10s"
[local.office.network]
local_ip = "127.0.0.1"
forward_local_ip = true

[[local.office.tunnel]]
id = 1
mode = "tcp"
port = 9001
bind = "127.0.0.1"
backend = [{ addr = "127.0.0.1:3000" }]
[local.office.tunnel.health]
type = "tcp"
interval = "10s"
timeout = "2s"
```

각 묶음은 `user`, `acl_mode`/`acl_rules`, `limits`, `network`, `dial_timeout`을 설정할
수 있고, 에이전트와 같은 TCP/UDP, HTTP/SNI, 프록시, 파일, 로드 밸런싱, 프로브, ACL
설정을 사용할 수 있습니다. 로컬 서비스만 운영한다면 클라이언트 테이블은 생략해도
됩니다.

로컬 묶음은 레지스트리와 트래픽 스냅샷에 `local.<name>`로 기록되며, **이 네임스페이스는
외부 에이전트의 key_id로 쓸 수 없습니다**. 로컬 묶음에는 브리지가 없으므로 업스트림
프록시 설정은 거부됩니다. `forward_local_ip = true`에서만 이그레스 IP를 백엔드에
사용합니다. 파일 루트, 인증서, 백엔드 설정은 시작 시점에 준비되며, 리스닝 충돌이 있으면
그 서비스는 시작되지 않습니다.

## 백엔드 별칭

| 주소 | 동작 |
| --- | --- |
| `tunnel://local.office/7` | 다른 등록된 로컬 터널의 서비스 진입점으로 들어갑니다 |
| `tunnel://agent-1/7` | 온라인 상태인 에이전트의 등록된 터널로 들어갑니다 |
| `file://agent-1/7` | 위와 같지만 등록된 대상이 `file` 모드여야 합니다. 디렉터리 경계, 읽기 전용 상태, 파일 인증은 그대로 유지됩니다 |
| `bridge://tcp`, `tls`, `ws`, `wss` | 대응하는 브리지 진입점으로 들어갑니다. 에이전트 쪽에서는 상호 인증이 여전히 필요하며, TLS는 브리지 인증서를 사용합니다 |
| `bridge://http` | 서버의 HTTP 진입점으로 들어가며, Host, 사이트 인증, 권한 검사가 계속 실행됩니다 |
| `bridge://web` | 관리 엔드포인트에 연결하며, 같은 방식으로 인증합니다 |

터널 번호는 명시적이고 안정적이어야 합니다. `user`가 있는 로컬 묶음은 같은 사용자의
대상만 참조할 수 있고, `user`가 없는 묶음은 서버 운영자가 관리하며 사용자를 넘어
참조할 수 있습니다. `bridge` 별칭은 운영자 묶음에만 허용됩니다. 원격 에이전트와 동적
프록시 요청은 별칭을 네트워크 대상으로 쓸 수 없습니다.

별칭에는 `backend.tls`, 네트워크 헬스 프로브, 진입점 대상 ACL이 추가로 적용되지
않습니다. 권한은 각 홉의 대상이 집행합니다. HTTPS/SNI 별칭은 TLS 데이터를 직접
전달할 수 있으며, 대상 사이트가 이를 종료하거나 통과시킵니다. UDP는 UDP로만 중첩할
수 있고, 다른 모드는 스트림 진입점을 사용합니다. SOCKS5/HTTP 프록시 인증은
건너뛰지 않습니다.

## 루프 제어와 계정 처리

- 모든 홉은 원래 출발지 IP와 포트, 라우팅 이력을 유지합니다.
- `(client, id)`가 반복되거나 홉이 **16개**를 넘으면 즉시 거부합니다.
- HTTP 연결 풀도 이력으로 분리되므로, 재사용한 연결로 루프 검사를 우회할 수 없습니다.
- 실제로 지나는 모든 터널은 각자의 연결 허용량을 갖고 트래픽을 기록합니다. 같은
  사용자나 묶음이 여러 홉을 지나면 홉마다 합산 할당량도 함께 부과됩니다.
- UDP 계정 처리는 메시지 페이로드를 포함하고 내부 길이 프레임은 제외합니다.

## 자주 쓰는 패턴

| 상황 | 방법 |
| --- | --- |
| 서버 호스트의 서비스도 노출하기 | `[local.ops]` + `[[local.ops.tunnel]]` |
| 내부 서비스 앞단에 TLS 오프로드 추가하기 | `tls_mode = "offload"`를 쓴 로컬 묶음의 HTTP 터널 |
| 내부 서비스 위에 사이트 인증 같은 진입점을 하나 더 얹기 | 백엔드를 `tunnel://agent-1/7`로 쓴 바깥쪽 로컬 묶음 |
| 내부 서비스에서 관리 엔드포인트 인증 재사용하기 | 백엔드를 `bridge://web`로 작성 |
